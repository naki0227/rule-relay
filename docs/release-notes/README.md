# リリースノート（docs/release-notes/）

- `<タグ>.md`（例 `v0.3.0.md`）は、そのタグの GitHub Release の本文になる。CI の release ジョブが、自動の変更一覧の前に置く（`.github/workflows/ci.yml`）。
- 遊ぶ人に向けて、何が変わったか・どう遊ぶか・起動できないときの対処を書く。開発の記録・設計の理由は `docs/adr/` と `docs/reports/` に置く。

## 生成 AI の利用はリリースノートに書かない

- **本人の決定（2026-11-22）**: GitHub Release のページから「生成 AI の利用」の節を、本人が意図して外した。これからのリリースノートにも、この節を足さない。
- AI の使用の記録（ツール・モデルとバージョン・使った工程・時期）の正本は [`docs/ai-usage.md`](../ai-usage.md)。コンテストの申告（企画書の「AIツール名、AIモデルおよびバージョン名およびその使用箇所」）は、そこから写す（`docs/submission/proposal-draft.md` 3.6）。
- 公開済みの Release とリポジトリをそろえるため、`v0.3.0.md` からも同じ節を消した（2026-11-22）。
