# ゴールの窪みの敵対的な試遊（2026-11-20）

- 対象: main（`claude/goal-probes` の分岐元）の、窪みのゴールを持つ 7 つのステージ（導入 `intro_jump_lend`／丘の上の旗 `hill_top`／採石場 `quarry`／三つの鐘の島 `three_bells`／浮島めぐり `floating_isles`／風の尾根 `windy_ridge`／古い砦 `ruined_fort`）。設計は ADR 0011 決定 9・10（クリアは「島の条件＋生きている全員がゴールの窪みに集まる」、窪みは縁より 1 段低い）。
- 方法: `tests/integration/test_goal_probes.gd`（13 件）。
  - プレイヤーと同じ操作（歩く・跳ぶ・渡す・F・V・メニューの「島のはじめから」）だけで遊んだ。動かすのは `move_intent`・`view_yaw`・`press_action` だけ。
  - 照準はゲームと同じく、`CameraRig` の yaw・pitch を回して `GameWorld.aimed_block()` のカメラの光線で決めた。pitch は CameraRig の範囲（-70°〜+30°）に収めた。
  - 2 人の協力は `test_net_director` と同じ形にした。同じプロセスの中にホストと参加者を別々の物理世界で作り、ENet でつないだ。
  - 測定の準備として、次の 3 つだけは位置を直接置いた。
    - 窪みの床の各点からの見通しを測るとき、観察者を床の各点に置いた。
    - 下で待つ仲間を、通信の操り人形と同じ `WorldParty.add_avatar` で置いた。
    - 2 人のテストの始めに、2 人を頂上・岩棚の縁に置いた（`test_net_director` の既存テストと同じ）。
  - ゴールへ歩いて入れることは、`test_goal_sightlines`・`test_open_islands` で確かめ済み。
  - 「窪みの中から渡せる」と判定したものは、どれも歩いて入る通しの操作でも再現した。
- 実行: `timeout 900 godot --headless --fixed-fps 60 --script res://tests/run_tests.gd -- --filter=goal_probes` で 13 件成功（約 16 秒）。`timeout 1200 tools/check.sh` は「all checks passed」（411 件）。
- `test_gate_*` は守られていた関所、`test_finding_*` は**試遊した時点の挙動**。
- `src/` は変えていない。数値はすべてヘッドレス・60fps の自動プレイで測った。

守られていた関所:
- **窪みの床に立ったままでは、開けた島 6 つで下の仲間を狙えない。**
  - 床を 0.5 おき（壁から 0.3 内側）に、合わせて 15〜65 点試した。下の仲間は、各島の登り口の下 1〜2 か所に置いた。
  - 仲間の体の高さ 0.1〜1.58 のどこにカメラを向けても、照準は合わなかった（11 か所すべてで 0 点）。
  - 必要な pitch は -14°〜-20° 程度で、CameraRig の下限 -70° には遠い。カメラを下へ向けきれないことが効いているのではない。効いているのは縁の地形。
- **窪みの罠**（浮島めぐり、ひとり）:
  - ジャンプを遠くの地面へ繰り返しで貸してから窪みに入ると、ひとりでは出られない。東西南北の縁へ 150 コマずつ歩き、止まったら跳ぶ操作をしても出られなかった。
  - 戻り道はどちらも効いた。V（1 票で成立）では島のはじめへ戻り、ジャンプも戻った。メニューの「島のはじめから」では、島を作り直した。
- **窪みの罠**（丘の上の旗、2 人）:
  - B が A へジャンプを渡して窪みに入ると、B ひとりでは出られない。
  - 縁の A が B に照準を合わせてジャンプを渡せば、B は自分で跳んで出られた。
  - V は 2 票要る。B の 1 票では戻らず、A も賛成すると戻った。
- **鐘**（三つの鐘の島）:
  - A が発射台に「投げる」を渡して東の鐘を鳴らした。そのあと B が発射台を F で回収しても、鐘は「鳴らした」まま数えられた（`activated` は消えない）。
  - B ひとりの投票では、10 秒待っても戻らなかった。
- **死亡と途中参加**:
  - 仲間が死亡観戦なら、ゴールにいる生存者だけでクリアした。死亡観戦の人も報酬を受け取った。
  - 途中で入って待機観戦している人は、クリアを止めなかった。待機観戦の人は報酬の対象外。

## 窪みの中から下へ渡す

### G1 導入の窪みは、立ったままで縁越しに下が見える（抜け道・小）

- 島: intro_jump_lend。岩棚の上面は y = 2、窪みの床は y = 1。窪みの南の縁は 1 マス（z = -6〜-5）。
- やったこと:
  1. 窪みのブロックで岩棚へ上がり、窪みに歩いて入った。
  2. 南の列（0.5, 1.0, -6.4）に立ち、下の地面（0.5, 0.0, -3.5）に立つ仲間へカメラを向けた。
  3. 合った照準のまま、ジャンプを渡した。
- 起きたこと:
  - 床の 27 点のうち 9 点（南の 2 列、南の壁から 0.3〜0.65）で、仲間の頭（足もと + 1.5〜1.58）に照準が合った。pitch は約 -14°〜-19°。
  - 胸から仲間の足もとまでは 3.60 で、触る届き（3.5 + 0.5 = 4.0）の内側。導入には「投げる」がないが、触るだけで渡せた（`test_finding_intro_gives_down_from_the_hollow_floor`）。
- 理由:
  - `CameraRig` は頭の上 1.5（足もと + 1.5）を中心に回る。カメラの光線は、いつもこの点を通る。窪みの床に立つと、この点は縁の上面より 0.5 高い。
  - 既存の `test_goal_sightlines` は、胸（足もと + 1.0 ＝縁と同じ高さ）からの光線で確かめていたので、この 0.5 の差を見ていなかった。
  - 縁が 1 マスだと、0.5 高い点から下の人の頭へ引いた線は、縁の角の上を通る。
- 計算での余裕（丘の上の旗）: 縁が 2 マスの丘の上の旗でも、余裕は小さい。
  - いちばん南の点（z = -5.3、回転の中心 y = 4.5）から、段丘の仲間の頭（z = -1.5、y = 3.58）へ線を引くと、縁の端（z = -3）での高さは約 3.94。縁の上面 4.0 との差は約 6 cm。
  - 縁を 1 マス狭めたり、下の待ち場所を崖から離したりすると、見えるようになる。
- 直し方の案（地形だけで）:
  - 導入の岩棚を南へ 1 マス広げ、窪みの南の縁を 2 マスにする。たとえば岩棚を z = -9〜-5 にし、ブロックの窪みを z = -4 へ動かす。直したら、この `test_finding_*` を `test_gate_*`（0 点）に書き換える。
  - 窪みを 2 段にするのは不可。自分のジャンプ（1.3）で出られなくなる。

### G2 窪みの中で跳ぶと、縁の上から下へ渡せる（抜け道・小）

- 島: intro・hill_top・quarry・floating_isles・windy_ridge・ruined_fort。
- やったこと:
  1. 窪みの床の 5 点（真ん中と四隅）から、真上に跳んだ。
  2. 跳んでいる間、毎コマ仲間の頭へカメラを向けた。
  3. 足もとがゴールの箱の中にあるコマで、照準が仲間に合うかを数えた。
- 起きたこと（合った点 / 5 点）:

  | ステージ | 下の仲間の足もと | 立ったまま | 跳んで |
  |---|---|---|---|
  | intro_jump_lend | (0.5, 0, -3.5) 地面 | 9 / 27 | 5 / 5 |
  | hill_top | (0.5, 2, -1.5) 段丘 | 0 / 15 | 5 / 5 |
  | hill_top | (0.5, 0, 5.5) 浜 | 0 / 15 | 5 / 5 |
  | quarry | (1.5, 3, -7.5) 北の出っ張り | 0 / 65 | 0 / 5 |
  | quarry | (0.5, 0, 0.5) 底 | 0 / 65 | 3 / 5 |
  | three_bells | (0.5, 3, -16.5) 段 | 0 / 27 | 0 / 5 |
  | three_bells | (-0.5, 0, -13.5) 原っぱ | 0 / 27 | 0 / 5 |
  | floating_isles | (-3.5, 0, -4.5) 真ん中の島 | 0 / 27 | 4 / 5 |
  | windy_ridge | (-1.5, 4, -18.5) | 0 / 27 | 5 / 5 |
  | windy_ridge | (4.5, 2, -22.5) | 0 / 27 | 0 / 5 |
  | ruined_fort | (6.5, 2, -14.5) | 0 / 27 | 3 / 5 |
  | ruined_fort | (0.5, 0, -4.5) 中庭 | 0 / 27 | 0 / 5 |

- 通しの操作でも再現した（`test_finding_hill_top_jump_and_give_from_inside_the_goal`）:
  1. 丘の上の旗で、窪みのブロックで頂上へ上がり、窪みに歩いて入った。
  2. 「投げる」の届き方にして跳び、空中で段丘の仲間へジャンプを渡した。
  3. 渡したコマも、着地したあとも、足もとはゴールの箱の中だった。仲間はジャンプ ×2 になった。
- 理由:
  - 跳ぶと回転の中心が 1.3 上がり、縁の上面より 1.8 高くなる。
  - 仲間へ渡す操作（`GameWorld._give_to`）は、床に立っているかを見ない。
  - ゴールの箱の高さは床から 3.0 あるので、跳んでいる間も「ゴールの中」に数えられる。
- 影響:
  - 窪みが防ぐのは「立ったまま」の受け渡しだけ。「ゴールに入ったまま下へ渡す」は、跳ぶだけでできる。
  - ただし、縁へ 1 歩出ても同じことができる（本人の判断で、縁から渡すのは許している）。手間の差は小さい。
  - 三つの鐘・採石場の出っ張り・風の尾根の西・砦の中庭のように、下の人が崖のすぐ下にいるか遠くて低い所は、跳んでも見えなかった。
- 直し方の案:
  - 地形だけで止めるには、窪みを深くするしかない。そうすると自分のジャンプで出られなくなる。縁を高くしても（縁の外側に 1 段の塀）、頂点（床 + 2.8）からは越えて見える所が残る。
  - 「縁から渡すのは許す」と同じ扱いにして、`test_accepted_*` で固定するのが自然。本人の判断が要る。

## ゴールの数え方

### G3 縁の角に乗ったまま、ゴールに数えられる（軽微）

- 島: hill_top で測った。仕組みなので、窪みのゴールすべてで起きる。
- やったこと:
  1. 頂上の南の縁（高さ 4）から窪みの方（北）へ、1 コマだけ前へ進めて 20 コマ止まる操作を繰り返した（キーを短く押すのと同じ）。
  2. 毎回、足もとの位置と、ゴールの箱に入っているかを見た。
- 起きたこと:
  - 体の中心が窪みの縁（z = -5）を 0.02〜0.22 m 越えた所で、足もとの高さ 3.88〜4.00 のまま床に立っていた。足もとはゴールの箱（y = 2.9〜5.9）に入っていた。
  - 0.30 m 越えると、窪みへ落ちた。
  - 縁の角の上で 2 秒止まっても、そのまま立っていた。そこから段丘の仲間に照準が合い、投げてジャンプを渡せた（`test_finding_standing_on_the_rim_lip_counts_as_in_the_goal`）。
- 理由:
  - ゴールの箱は、水平方向が窪みの床と同じ広さで、高さが床 - 0.1〜床 + 2.9 ある。縁の上面（床 + 1）も高さの範囲に入る。
  - カプセル（半径 0.3）は、床の角が 50° 以内なら角に乗っていられる。そのため、中心が縁の外へ約 0.23 m 出るまでは落ちない。
- 影響:
  - 縁に立っている（＝下が見える）のに、ゴールに数えられる。G2 と同じで、「ゴールの中から下へ渡す」ができる。
  - 0.2 m 幅に止まる操作は難しいが、何度でも試せる。
- 直し方の案（ゴールの箱の形だけで。ルールは足さない）:
  - `OpenIslands.goal_hollow` の箱を、水平方向に 0.3（カプセルの半径）ずつ内側へ縮める。床に立つ人の中心は、もともと壁から 0.3 より近づけないので、窪みの中の人が数えられなくなることはない。
  - または箱の上端を床 + 0.9 にする（縁の高さを含めない）。跳んでいる間は数えられなくなるが、クリアは毎フレーム調べるので、着地すれば成り立つ。

## 協力での妨害

### G4 1 人の賛成票が残り、仲間が死んだ瞬間に全員リセットが決まる（妨害・中）

- 島: three_bells で測った。協力のどのステージでも起きる。
- やったこと:
  1. A（ホスト）が東の岸の発射台に「投げる」を渡し、東の鐘を鳴らした。
  2. B（参加者）が発射台を狙って F で回収した。
  3. B が V で全員リセットに賛成した（1 / 2 票）。10 秒待った。
  4. A が東の岸から谷へ歩いて落ちた。B は何もしなかった。
- 起きたこと:
  - 2 では、「投げる」は B の手元へ移った（B の「投げる」が 2 個、A は 0 個）。A へは戻らない。F の回収は回収した人の手元へ、という本人の確定ルールどおり。
  - 鐘は鳴らしたまま数えられた。
  - 3 では、10 秒たっても全員リセットは決まらなかった。ただし投票は開いたまま。
  - 4 では、A が死亡観戦になった瞬間、全員リセットが決まった。東の鐘は「鳴らしていない」に戻り、A の「投げる」は戻った（`test_finding_bell_griefing_recall_vote_and_the_dead_partner`）。
- 理由:
  - `PartyLifecycle` の投票には、時間切れや取り消しを呼ぶ所がない。`cancel_vote`・`withdraw_vote` はあるが、`src/` のどこからも呼ばれていない。`cancel_vote` のコメントには「時間切れなど」とある。
  - 「死亡観戦がいるとき、生存者全員の賛成でも成立する」（`SURVIVORS_CAN_RESET_EARLY`、仮）の判定は、人が死んだときにも行われる。
  - そのため、前に押した 1 票だけで、死んだ人に聞かずに成立する。
- 影響:
  - 妨害する人は、早めに V を押しておくだけでよい。仲間がうっかり落ちた瞬間、最後のチェックポイントより後の進み具合（鳴らした鐘・動かしたブロック）が消える。
  - 本来なら、死亡観戦の人は台座の F で、世界を戻さずに復活できる。
  - クリアできなくなるわけではない。遅くなるだけ。
  - 悪意がなくても起きる。窪みの罠で V を押したまま待っている人がいて、もう 1 人が落ちた、など。
- 直し方の案（どれも本人の判断が要る。妨害を「禁止」するのではなく、票の寿命の扱い）:
  1. 投票に時間切れを付ける（たとえば 20 秒で `cancel_vote`）。V を離したら取り消す、でもよい。
  2. 「生存者全員の賛成」の経路では、死亡が起きた後に入れた票だけを数える。
  3. いまのまま（仮の既定値）にして、`test_accepted_*` で固定する。

### G5 生きている 1 人がゴールに入らなければ、クリアしない（妨害・クリア不能）

- 島: intro で測った。「生きている全員がゴールに集まる」のステージすべてで起きる。
- やったこと:
  1. A が岩棚の窪みに歩いて入った。B は岩棚の縁に立ったまま、10 秒待った。
  2. B が岩棚から南へ歩き、島の端から落ちた。
- 起きたこと:
  - 1 の 10 秒の間は、クリアしなかった。
  - 2 で B が死亡観戦になると、A だけでクリアした。B も報酬を受け取った（`test_finding_one_player_outside_blocks_the_clear_until_they_die`）。
- 影響:
  - 妨害する人は、ゴールに入らず、落ちないでいるだけで、ステージをクリア不能にできる。投票や復活では外せない。
  - ほかの人ができるのは、部屋を出ることだけ。ホストが参加者を外す操作もない。
  - 能力を集めて離さない妨害も、組み合わせられる。F の回収で仲間の「投げる」を取り上げる（G4 で実測）、島の装備（ダッシュ・ブーツ・グローブ）を先に拾う、など。ただし、ゴールに入らないだけで十分なので、この組み合わせは確かめていない。
  - 受け取った人は、能力を手放させる手段を持たない。
- これは決定 9（全員で集まる）と「システムで妨害を止めない」の組み合わせの帰結で、不具合ではない。選択肢は本人が決める:
  - そのまま受け入れる（部屋を選ぶのは人の側）。
  - 部屋の主が参加者を外せるようにする。
  - 「ゴールに入らない人がいる」ことを HUD に出す。誰が止めているかを見えるようにするだけで、止めはしない。

## そのほか気づいたこと

- 窪みの罠で、相手が投票にもジャンプの返却にも応じないと、閉じ込められた人は出られない。出る手段は部屋を出ることだけ（G5 と同じ構図）。ひとりなら V とメニューで必ず戻れる。
- テスト中に一度、Jolt の警告「job system exceeded the maximum number of jobs」が出た（島の試遊の報告と同じ。ERROR ではない）。ステージを何度も作り直すテストで出る。
