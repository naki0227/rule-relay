# ADR 0007: 死亡観戦・共通チェックポイント・全員リセット投票のルール（PartyLifecycle）

- 状態: 採用（2026-11-20、P3-3。ルール層だけ。画面・通信・世界の復元への接続は後の段）
- 出典: `docs/handoff/2026-11-20-multiplayer-handoff.md` の 2-7、4.1〜4.3、5.2、7-2〜7-4、9 の 10〜15
- 関連: [ADR 0005](0005-party-token-ledger.md)（能力台帳）、[ADR 0006](0006-online-co-op-transport.md)（ホスト権威）

## 決定

1. **参加者の状態を純粋なルール `PartyLifecycle`（`src/rules/party_lifecycle.gd`）に置く。** ノード・物理・通信・`RuleLedger` には触らない。ホストがこれを持ち、通信から来た依頼（死亡・到達・投票など）を順に当てる。
2. **状態は5つ**: `ACTIVE`（正式参加・生存）、`DEAD_SPECTATING`（正式参加・死亡観戦）、`WAITING_SPECTATOR`（途中入室の待機観戦）、`LEFT`（明示的な退出）、`DISCONNECTED`（正式参加・通信切断）。退出と切断は分ける（報酬の真理値表 5.2）。切断した人の切断前の生死は覚えておき、再接続で戻す。
3. **死亡は状態を変えるだけ。** 台帳は何も変えない（貸している能力は貸したまま、手元の能力はそのまま）。ワープもしない（仕様 4.1【確定】）。テストで台帳のスナップショットが変わらないことを確かめる。
4. **共通チェックポイント**: 生存者の1人が着けば有効（過半数を待たない。4.1【確定】）。有効にした順に一覧で持つ。
5. **全員復活** は蘇生だけ。死亡観戦の全員を生存に戻し、世界・台帳は戻さない（4.1【確定】）。全員リセットとは別の操作にした（P4 の「蘇生と全員リセットを別の usecase に」）。
6. **全員リセット投票**: 部屋にいる正式参加者なら誰でも提案でき、母数の過半数（`floor(n/2)+1`: 1→1、2→2、3→2、4→3）で成立（4.2【確定】）。途中待機・退出・切断中は母数に入らない。同じ人の重複票は1票。投票中の提案は賛成票になる。取り下げ（`withdraw_vote`）と打ち切り（`cancel_vote`）がある。退出・切断した人の票は数えない。
7. **全員死亡・ソロの死亡は投票を待たずに自動で全員リセット**（4.1【方向】、ソロで永久観戦にならない【必須】）。戻り先は最新の有効なチェックポイント、無ければステージ開始（`STAGE_START = ""`）。
8. **全員リセットは指示を返すだけ。** `PartyResetDecision` に「戻す先のチェックポイント、リセット後に操作する人、待機から合流した人、人数別補助を何人用に組むか（前は何人だったか）、何回目のリセットか」を入れ、`take_pending_reset()` で受け取る。世界と台帳の復元は呼び出し側が1つのスナップショットで行う（4.2【確定】）。参加者の状態（全員生存・待機者の合流）だけはルール側で先に切り替える。`generation` は再送で二重に戻さないため（9 の 22）。
9. **人数別補助は全員リセットのときだけ組み直す**（2-7【確定】）。`headcount()` はステージ開始と全員リセットのときだけ変わり、途中入室・退出・蘇生では変わらない。補助そのものの組み直しは P3 のステージ側が `PartyResetDecision.headcount_changed()` を見て行う。
10. **報酬資格の問い合わせ** `reward_eligible_players()`: 生存・死亡観戦・切断中は対象、途中待機と退出は対象外（5.2【確定】）。報酬台帳は別の段で作る。
11. **スナップショットの順序**（4.2【未決】への対応）: `activate_checkpoint` が true を返したとき（そのチェックポイントを初めて有効にしたとき）だけ、呼び出し側がその場でスナップショットを採る。そのとき死亡観戦中の人を、死んだ場所に生きている人として記録しない（チェックポイントの出現位置で記録する）。全員復活ではスナップショットを採らない・戻さないので、二重復元は起きない。
12. **保存**: `to_dict()` / `PartyLifecycle.from_dict()` で状態をまるごと保存・復元できる（ホスト移譲 P5 用）。未受領の `PartyResetDecision` も含む。仮の設定（下の3つ）は保存しない（コードの既定値に従う）。

## 未決のため仮にした挙動（本人の判断待ち）

切り替えは `src/rules/party_lifecycle.gd` 冒頭の定数1か所（部屋ごとに変えたいときは同名の変数）。

| 仕様の項目 | いまの挙動 | 切り替え |
|---|---|---|
| 7-2 古いチェックポイントで何度でも全員復活できるか | できる（有効にしたチェックポイントならどこでも） | `REVIVE_AT_OLDER_CHECKPOINTS` |
| 7-3 死亡者の通常投票権 | 死亡観戦者も票を持ち、母数にも入る | `DEAD_CAN_VOTE` |
| 7-3 過半数と「生存者全員の同意」の関係 | どちらか一方を満たせば成立（並列の経路）。生存者全員の経路は死亡観戦者がいるときだけ。両方満たせば理由は過半数 | `SURVIVORS_CAN_RESET_EARLY` |
| 7-2 全滅自動リセットの範囲 | 生存者が0人で、死亡観戦か待機の人が部屋にいれば自動で戻す。最後の生存者が切断・退出した場合も含む。正式参加者が全員抜けて待機の人だけが残った場合も、待機の人を合流させて戻す | `_after_change()` |
| 7-4 人数別補助の人数の数え方 | リセット後に部屋にいて操作する人の数（切断中の人は数えない） | `_full_reset()` |
| 4.1 既に有効なチェックポイントへの再到達 | 何も変えない（スナップショットを採り直さず、最新の戻り先も変えない） | `activate_checkpoint()` |
| 4.3 退出した人が同じステージへ戻る | 待機観戦からやり直す（その回の報酬資格は次の全員リセットまで無い） | `join()` |
| 4.1 切断中に全員復活があった場合 | 切断中の死亡者は戻さない。再接続すると死亡観戦に戻り、次の全員復活で戻る | `revive_all()` |
| 4.3 待機観戦の人の切断 | 記録から外す（まだ参加していないので報酬にも関わらない） | `disconnect_player()` |

**確定（2026-11-21 本人。AI の判断を採用）**: ホストがクリア前にメニューの「ゲームをやめる」を選んだら、退出ではなく
**通信切断（`DISCONNECTED`）と同じ扱い**にする（退出は送らない）。残った人はホスト移譲で部屋を続け、部屋が残っている間に
戻れば報酬を受け取れる（経緯は `docs/reports/2026-11-21-v0.2.0-review.md`、ADR 0006・0010）。

蘇生の操作導線・アニメーション・無敵時間・蘇生の正確な配置（7-2）、投票の時間切れの長さ、ホスト移譲中の投票の例外（7-1）はこのルールの外で、まだ決めていない。

## 採らなかった案

- **死亡を `RuleLedger` の操作にする**（死者の能力を落とす・器へ戻す）: 仕様が「死んだだけでは落とさない、再生成しない」と確定している。台帳を触らないのが最も確実。
- **全員リセットの中で世界と台帳を戻す**: ルール層が `WorldSnapshot`（ノード）に依存する。決定だけを返し、復元は世界側で1回だけ行う方が、二重復元を避けやすく、テストも純粋に書ける。
- **既存の `CheckpointHistory` をそのまま使う**: 1人用で、保存の順番だけを持ち古いものを捨てる（CAPACITY 3）。チェックポイント ID ごとのスナップショットの持ち方は、世界側へ接続する段で決める。
- **入室したらすぐ合流させる**: 仕様 4.3 が「新規入室だけで全員を勝手にリセットしない」「次の全員リセットで合流」と決めている。
