# ADR 0015: 風・氷・水と流れ、新しい能力「重い・浮く・泳ぐ」

- 状態: 採用（2026-11-21。仕掛けと能力のコードとテストまで。これを主役にしたステージ 3-4・5-4・4-4・6-1・6-4 はまだ作っていない）
- 決めた人: AI（本人の原則と依頼の範囲の中で決めた。数値はすべて仮で、本人の試遊で直す）
- 依頼（2026-11-21、ADR 0013 の次の段階）: 計画の「要実装」のうち、風・氷・水と流れ、能力 HEAVY（4-4）・
  FLOAT（6-1）・SWIM（6-4）を作る。重さの板・スイッチの扉・時の鐘・ワープの石は別の作業（`claude/gimmicks-a`）。
- 守る原則（変えない）: 「ルールは厳格に。解法は自由に。」／自由な遊びを止めるシステムのルールは足さない（地形で作る）／
  能力は貸せるトークンで、プレイヤーにも、意味があればブロック・生き物にも効く／1〜4 人の協力でホスト権威、全部を同期し、
  チェックポイントで記録・復元する／ゆるふわの見た目。
- 関連: ADR 0003（ルールの層と物理）、0005（能力の台帳）、0006（通信）、0007（死亡と観戦）、0009（ステージの定義）、0013（キャンペーン）

## 決定

### 1. 置き方（`StageDef`）

- **風・水は `StageDef.nature`（`NatureLayout`）**に置く。純粋なデータ。
  - `add_wind(min, max, 向き, 強さ)`／`add_pulsing_wind(min, max, 向き, 周期, 吹く秒, ずらし)`
  - `add_water(min, max)`／`add_current(min, max, 向き, 速さ)`
  - 範囲はセル（両端を含む）。向きは東西南北だけ（ブロックをマス単位で運ぶため）。
- **氷は地形の種類 `"ice"`**（`terrain_boxes`）。新しい地形の仕組みは作らず、どのセルにも能力を渡せる、のまま。
  氷のセルを動くブロックにすると `ice_cell` のモデルになり、上に乗ってもすべる。
- `StageDef.problems()` が `NatureLayout.problems()` も見る: 斜めの向き・強さ 0・脈の時間の矛盾・**水の下に地形がある**を誤りにする。

### 2. 水は底なし。泳げずに落ちたら「島から落ちた」のと同じ

- 水の範囲の下には何も置かない（地形で決める。`problems()` が確かめる）。泳げない人・重い人は水の中を沈み
  （6 m/秒）、`FALL_LIMIT_Y` を下回ると、これまでの「落ちた」と同じ流れになる:
  ステージでは死亡→観戦（`PartyDirector._check_deaths`）、広場では出現地点へ戻る、ひとり用の `GameWorld` では保存へ戻る。
- **新しい死に方・判定を足さなかった**（「水に入ったら即死」の判定を作ると、死亡・観戦・全員復活・ホスト移譲の
  どこにも新しい分岐が要る）。沈む間（約 2 秒）は、誰かが「泳ぐ」「浮く」を投げ渡せば助かる（解法は自由）。
- 浮かないブロックも沈み、島から落ちたブロックと同じく元の位置へ戻る（`WorldTicks.rescue_lost`。貸した能力は貸した人へ）。
  生き物も同じ（元の場所へ）。

### 3. 能力の意味と ×n（`Tuning.stack_factor` と同じく「数に比例」）

| 能力 | 持っているとき（プレイヤー） | ブロック・生き物 | ×n |
|---|---|---|---|
| 重い（HEAVY） | 風に流されない・水に沈む（泳げても）・重さの板に 4 人分 | 風に運ばれない・水に沈む | 板の上の重さが 4n 人分（`BodyTraits.weight_units`）。風は ×1 で完全に効かない |
| 浮く（FLOAT） | 空中で落ちる速さが 1.6 m/秒まで・水に浮く（自分では進めない。流れに乗る） | 空中でゆっくり落ちる・水に浮いて筏になる（上面が岸とそろう） | 落ちる速さの上限が 1/n（n 倍ゆっくり、同じ高さから n 倍遠くへ） |
| 泳ぐ（SWIM） | 水に浮かび、W/A/S/D で 2.5 m/秒で進める・水面から跳べる | 生き物は水に浮く | 速さが n 倍。流れ（既定 3 m/秒）に ×1 では逆らえず、×2 で逆らえる |

- **重いと浮くは数で打ち消し合う**: 重さ = 重いの数 − 浮くの数。正なら重い、負なら浮く、0 ならふつう。
  「どちらを優先するか」の決まりを足すより、数だけで説明できる（ルールは厳格）。
- 禁止を持っていれば、その性質は 0 個と同じ（例: 泳ぐの禁止を拾うと沈む）。
- 3 つとも「持っているだけで効く性質」で、キーも発動方式も無い（`RuleAction.is_triggered` は false。投げる・登ると同じ）。
  ブロックへは方式なしで付く。能力が自分に効くのは、ほかの能力と同じくホットバーにある間だけ。
- **浮くを「宙に止まる」にしなかった**: 計画の表は「ブロックに渡すと宙に止まる」だったが、プレイヤーとブロックで意味が
  変わる。どちらも「ゆっくり落ちる」にそろえた（×4 ならほとんど止まって見える）。
- **重さの板への入口**: 板（別の作業）は `BodyTraits.is_heavy(ledger, id)` と `weight_units(ledger, id)` だけを見ればよい。
  id はプレイヤー ID でもブロック・生き物の ID でもよい。

### 4. 動き方

- **風**: 範囲の中のプレイヤー・生き物に、風の速さ（3 m/秒）を足す（空中でも）。歩く速さ 5 より遅いので、逆らえば遅くても進める。
  ブロックは床に立って止まっていれば 0.9 秒ごとに風下へ 1 マス、落ちている器も 0.9 秒ごとに 1 マス。
  脈打つ風は `周期` 秒ごとに `吹く秒` だけ吹く。
- **氷**: 床が氷なら、勢いを望む速さへ 2 m/秒² でしか寄せない（止まれない・曲がれない）。氷から跳んだ・落ちたときも
  勢いは残り、氷でない床に着くと消える。ブロックは横の移動を最後まで進み切った後、下が氷なら同じ向きにもう 1 マス
  （0.3 秒）すべり、塞がれるか氷が終わるまで続く。ダッシュの後も同じ。
- **水と流れ**: 浮く・泳げる人は足が水面の 0.45 m 下に浮かび、水面から跳べる（岸の高さは跳んで上がる）。
  流れには誰でも運ばれる（沈んでいる人も）。浮いたブロックは床に立つのと同じ扱いで、自分の W/A/S/D・ジャンプも使え、
  流れに 0.9 秒ごとに 1 マス運ばれる。上に乗った人も一緒に運ばれる（ブロックは今までどおり同期移動の床）。
- **外の力は禁止で止まらない**: 風・氷・流れはブロックの「行動」ではない（`RuleBlock.push`。下から押し上げられるのと同じ）。
- **器は崖の下へ落とさない**: 風・流れは、いまの高さから上下 0.5 以内の上面か、水面へだけ器を運ぶ（壁は越えない）。
  器は物理を持たないので、崖から落ちて取れなくなるのを地形で防ぐ。

### 5. 通信と記録

- 置き方は同期しない。どの画面も同じ `StageDef.nature` から作る（`NatureBuilder`）。
- **自分のアバターは自分の画面で風・氷・水を受ける**（`PlayerAvatar` → `NatureMotion`）。位置はこれまでどおりホストへ送る
  （ADR 0006 のアバターの扱いのまま）。沈んだ参加者の死亡は、ホストが位置で判定する。
- **ブロック・生き物・器はホストが動かす**（`NatureTicks`。`GameWorld._physics_process` の `WorldTicks` の後）。
  ブロックと生き物の位置は `WorldFrame`、器の位置は台帳の写しで届く。
- **脈打つ風の時計**（`NatureField.clock`）は参加者も進め、ホストが `WorldFrame` の `"nature"` で配る値に合わせる。
- チェックポイント（`WorldSnapshot`）とホスト移譲の引き継ぎに、時計とブロック・器を運ぶ途中の経過時間を入れる。
  氷の上の勢い（`PlayerAvatar.slide`）は、復元で 0 にする。

### 6. 見た目（Blender: `art/scripts/build_nature.py`）

- 風: 風上の端に立つ**かざぐるま `wind_fan`**（石の台・木の柱・風見の尾・4 色の花びら）。骨 `b_root`（柱）・`b_rotor`（羽根）の
  骨格で、羽根はアクション `spin` で回る（2026-11-21 本人の指示どおり、部品＋骨格＋アクション）。吹いていない間はゆっくり回る。
  範囲には若葉色の**木の葉 `wind_leaf`** が流れる（`CPUParticles3D`。吹いていない間は止まる）。
- 氷: 地形のメッシュの色を淡い水色にし、上面に透けてつやのある霜の板を重ねる（`IceFrost`）。動くブロックにした氷は `ice_cell`。
- 水: 透ける空色の水面（ゆっくり上下）と、下へ濃くなる水の柱。流れがあれば水面を泡が流れる（`WaterVisual`）。
- 拾える物: 重い＝取っ手の付いた丸い石のおもり `heavy_weight`、浮く＝空色の風船 `float_balloon`、泳ぐ＝空色の足ひれ `swim_fins`。
  アイコン（`build_icons.py`）: おもり・風船・二本の波。

## 採らなかった案

- **水に入ったら即「溺れた」判定**: 死亡・観戦・全員復活・ホスト移譲に新しい分岐が要る。底なしにすれば、今の「落ちた」がそのまま使える。
- **水に底を作り、泳げない人は底を歩く**: 依頼（泳げなければ落ちたのと同じ）と違い、川が「歩いて渡れる溝」になる。
- **重いを常に優先（浮くと両方あれば重い）**: 優先の決まりを 1 つ足すことになる。数で打ち消す方が説明が短い。
- **ブロックの浮き沈みをブロックごとの設定（木の箱は浮く等）にする**: 見た目で決まる隠れたルールになる。「浮く」のトークンだけで決め、
  筏はステージに「浮く付きのブロック」として置く（回収すれば沈む＝解法になる）。
- **プレイヤーの風・水もホストが計算して位置を送る**: 今の通信は自分のアバターを自分で動かす形（ADR 0006）。仕掛けだけ
  ホストで動かすと、入力の遅れで風の中だけ操作感が変わる。
- **調整値を `Tuning` に足す**: 並行の作業と同じ場所を書き換えるので、`NatureTuning` に分けた。

## まだやっていないこと・仮の点

- これらを主役にしたステージ（3-4 風の通り道・4-4 重さの板・5-4 氷の庭・6-1・6-4 流れる川）。見本の小さな島は
  `tests/integration/test_nature_stage.gd` の `demo_stage()`。
- 上向きの風（浮くと組み合わせて昇る）。向きは東西南北だけ。
- 生き物の判断（`CreatureMind`）は水・風を知らない（風で押されると道を選び直す。水を渡る道は選ばない）。
- 壊れる床（重いで割れる）は作っていない（依頼で任意）。
- 広場のホットバーは 9 枠なので、能力を全部開ける（W/A/S/D・ジャンプ・投げる・ダッシュ・重い・浮く・泳ぐ）と泳ぐが入らない。
  広場の能力の置き場は、キャンペーンの開き方を本人と決めるときに直す。
- 数値（風 3 m/秒・氷 2 m/秒²・泳ぐ 2.5 m/秒・流れ 3 m/秒・浮く 1.6 m/秒・沈む 6 m/秒・運ぶ間隔 0.9 秒・重い 4 人分）はすべて仮。
