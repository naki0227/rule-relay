# ADR 0003: ルール層と物理層の分離、ブロックの動かし方

- 状態: 採用（2026-11-18、P0 試作の段階）

## 決定

1. **ルールは `src/rules/` の純粋なクラスに置く**（`RuleLedger`・`BlockRules`・`RepeatCursor`・`InputRouter`）。
   ノード・入力・物理に依存させず、単体テストで確定仕様を固定する。物理の状態（床にいるか、進路が空いているか）は呼び出し側が真偽値で渡す。
2. **トークンの所有は `RuleLedger` だけが持つ**。ブロックやプレイヤーのノードは能力を保持せず、毎回 ledger に問い合わせる。チェックポイントは ledger の snapshot とノードの位置・速度を一緒に保存して、丸ごと戻す。
3. **ブロックは AnimatableBody3D＋自前の運動学**。重力と1ブロック移動を自分で計算し、`test_move` で衝突を確かめてから `sync_to_physics` の同期移動で反映する。
   - プレイヤーとは衝突判定しない（ブロックの collision_mask にプレイヤーを含めない）。乗っている人に押し戻されてジャンプが止まることがない。
   - プレイヤー（CharacterBody3D）は床の速度を引き継いで運ばれる。重力をプレイヤーと同じにして、上昇・減速中に足場から離れないようにした。
   - 隣のブロックと一体化しない（企画書 4-3）。上昇中に上のブロックへ当たったら、その速度で押し上げる（禁止は外力を妨げない: 企画書 4-4）。横方向の押し合いは P0 では行わず、塞がれたら止まる。
4. **入力は `PlayerInput`（UI 側）が `GameWorld` の操作メソッドへ変換する**。結合テストは同じメソッドを呼ぶので、キー入力なしで解法を最後まで再生できる。

## 採らなかった案

- **RigidBody3D のブロック**: 隣接ブロックとの摩擦・積み重ねの揺れで、ルールどおりの「1回のジャンプ」「1ブロックの移動」が読みにくくなる。パズルとして予測できる動きを優先した。
- **CharacterBody3D のブロック**: キネマティック同士は押し合わないため、乗っているプレイヤーにぶつかって上昇が止まる。
- **連結した隣接ブロックを一体の剛体にする**: 本人が明確に不採用とした（コンセプトノート 2026-11-17）。

## 見直し条件

- Windows 実機で、乗車中の振動・すり抜けが目立つ（ヘッドレスの固定 60fps では未発生）。
- 生き物を入れる P1 で、ブロックと生き物の押し合いが必要になったとき（横方向の外力を設計し直す）。
