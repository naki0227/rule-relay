# ADR 0003: ルール層と物理層の分離、ブロックの動かし方

- 状態: 採用（2026-11-18、P0 試作の段階。決定 5 は 2026-11-21、決定 6〜8 は 2026-11-21 の本人の試遊を受けて追加）

## 決定

1. **ルールは `src/rules/` の純粋なクラスに置く**（`RuleLedger`・`BlockRules`・`RepeatCursor`・`InputRouter`）。
   ノード・入力・物理に依存させず、単体テストで確定仕様を固定する。物理の状態（床にいるか、進路が空いているか）は呼び出し側が真偽値で渡す。
2. **トークンの所有は `RuleLedger` だけが持つ**。ブロックやプレイヤーのノードは能力を保持せず、毎回 ledger に問い合わせる。チェックポイントは ledger の snapshot とノードの位置・速度を一緒に保存して、丸ごと戻す。
3. **ブロックは AnimatableBody3D＋自前の運動学**。重力と1ブロック移動を自分で計算し、`test_move` で衝突を確かめてから `sync_to_physics` の同期移動で反映する。
   - プレイヤーとは衝突判定しない（ブロックの collision_mask にプレイヤーを含めない）。乗っている人に押し戻されてジャンプが止まることがない。
   - プレイヤー（CharacterBody3D）は床の速度を引き継いで運ばれる。重力をプレイヤーと同じにして、上昇・減速中に足場から離れないようにした。
   - 隣のブロックと一体化しない（企画書 4-3）。上昇中に上のブロックへ当たったら、その速度で押し上げる（禁止は外力を妨げない: 企画書 4-4）。横方向の押し合いは P0 では行わず、塞がれたら止まる。
4. **入力は `PlayerInput`（UI 側）が `GameWorld` の操作メソッドへ変換する**。結合テストは同じメソッドを呼ぶので、キー入力なしで解法を最後まで再生できる。
5. **ブロックの W/A/S/D は予約できる**（2026-11-21 本人の判断「W とかの単発がシビアなんよ　いちます進ませてな？　繰り返しの時も予約にしといて」。`src/game/block_move_buffer.gd`）。
   - 単発（キー）・繰り返し（周期）・信号で W/A/S/D を起動したとき、ブロックが空中にいるか前の1マス移動の途中なら、失敗にせず予約する。地面に落ち着いていて進む先が塞がれているときは、今までどおりその場で失敗。
   - 予約は「横に動いていない」かつ「進む先のマスが**いまの高さで**空いている」になった瞬間に、ちょうど1マス動く。**空中でも動き出してよい**ので、ジャンプ（2.5）→ W で、縁を越えたところで高さ 1〜2 の段へ乗る。動いたあとも重力は続く。空中で起動したときに進む先がすでに空いていれば、待たずにすぐ動く。
   - 着地（地面・水に浮く・登るでつかまる高さ）した時点で進む先が塞がれていれば、その予約は**失敗として使い切る**（壁が消えるまで待たない。押してからずっと後に急に動くのは読めないため）。安全のため最長 4 秒で失敗にする。
   - 1つのブロックに予約は1つだけ。繰り返しの周期が予約中に来たら、その周期は見送る（交互の順番は今までどおり進む）。予約中の単発トークンは、もう一度押しても起動しない。
   - 禁止と能力の判定は、動く瞬間に毎回やり直す（禁止が上位）。予約中に禁止が付いたら動かず、失敗として扱う。
   - 単発は、予約が動いた／失敗したと決まってから付与した人へ戻る（「起動したら使った扱い」は変えない）。範囲単発はブロックごとに予約し、全部の結果がそろってから戻る。予約中に F で回収すると予約は消える。
   - 空中で始めた1マス移動が途中で塞がれたら、マス目からずれたまま落ちないよう元のマスの列へ戻す。
   - 予約はホストだけが持つ一時的な状態で、チェックポイント・全員リセットには**保存せず、復元したら消す**（貸した単発は残るので、もう一度押せる）。参加者はホストから位置を受け取るだけ。
   - ジャンプとダッシュは予約しない。プレイヤーと生き物は対象外（生き物は単発・繰り返しを持たず、`can_initiate` で自分で判断するので別の経路）。

6. **同じ付与の W/A/S/D は、接しているブロックどうしでまとめて動く**（2026-11-21 本人の試遊「範囲のブロックで右に動かすとかでもさ、一気に一緒に動いてほしい。2×2 とかだったら先に右のやつだけ右に動いて、その次のティックで1マス開けた状態で一緒に動くみたいな感じになってる」。`src/game/block_move_buffer.gd` の `trigger_group`）。
   - 原因: 範囲で渡したブロックを1つずつ順に試していたので、後ろのブロックは前のブロックにまだ塞がれていて失敗し、前だけが動いた（繰り返しなら次の周期から1マス空いたまま一緒に動いた）。
   - 組: 1つのトークン（範囲付与）で同じ瞬間に起動した（同じ単発の押下・同じ周期の繰り返し・同じ周期の信号）ブロックのうち、面で接している（6方向）ものを1つの組にする。離れているブロックは今までどおり1つずつ。違う付与のブロックは、接していても別々に動く（今までどおり）。
   - 動くか: 組の全員が「仲間の空けるマスは空き」とみなして、いまの高さで1マス進めるときだけ、全員を同じフレームで動かす。先頭が壁に当たれば後ろも動かない。**組は固い**: 一部の列だけ進める場合も、組の形を崩さないよう全員止まる（2×2 の片方の列だけ塞がれていれば、どちらの列も動かない）。
   - 禁止・能力なしの仲間（例: 1つだけ D 禁止が付いている）は組から外れてその場に残り、ほかの仲間にとっては壁になる（禁止が上位）。
   - 空中・移動中: 組の誰かが空中か1マス移動の途中なら、組ごと予約する（決定 5 と同じ規則を組に広げた）。全員がいまの高さで進めるようになった瞬間に全員一緒に動く。全員が落ち着いても塞がれていれば組ごと失敗、最長 4 秒。単発は組の結果が出てから戻る。予約中に組の誰かを回収・禁止したら、そのブロックだけ組から外れる。
   - 動いている途中: 仲間どうしは同じ向き・同じ速さで動くので、横の当たり判定で互いを無視する（`RuleBlock._sweep` の exclude）。途中で誰かが塞がれたら、全員を同じだけ進んだ位置で止める（重なり・形の崩れを防ぐ）。
   - 隣のブロックと一体化しない（3 の方針）は変えない。組は「同時に動かす」だけで、物理では1つの物にならない（乗る・落ちる・押し上げるは1つずつ）。
   - 通信: ホストが決め、参加者は今までどおり位置を受け取る。予約はチェックポイントに保存しない（決定 5 と同じ）。
   - 地面に範囲で W/A/S/D を渡したとき: 地面の円は1つの組になり、外側の地形に塞がれるので動かない。以前は島の縁に面したセルだけが列ごとに順に落ちていき、立っている人ごと床が島の外へ流れた（下の「床が抜ける」の原因の1つ）。1マスだけ渡したセルは今までどおり動き、縁から押し出せば落ちる。
7. **ブロックに付いた禁止は、その上に立つ人にも効く**（2026-11-21 本人「ジャンプ禁止ってさ、そのブロックに働く感じになってるからさ、その上に乗ってもジャンプ禁止っていうのは適用してほしい」→「基本的に禁止はその上も禁止にしよう」。`src/game/floor_bans.gd`）。
   - 「立っている」: 床に着いていて（`is_on_floor`）、足の下へ 0.08m 動かしたときに当たるブロック（継ぎ目なら両方）。地形のセルへ渡した禁止は、そのセルが動くブロックになるので同じ。跳んでいる間・降りた後は効かない。乗っているブロックが持ち上げられていても、上に立っている間は効く。
   - 対象: プレイヤーと生き物。ブロックの上のブロックには広げない（ブロックは自分の禁止だけ。3 の「一体化しない」）。
   - 種類ごとの効き方:

     | 禁止 | 上に立つプレイヤー | 上に立つ生き物 |
     |---|---|---|
     | ジャンプ | 跳べない（ブーツの高跳びも） | 跳ばない。そのマスから跳ばないと上がれない段へは道を選ばない |
     | 高跳び | ブーツの高さが出ない（ふつうのジャンプはできる） | 高跳びしない |
     | ダッシュ | 地上からダッシュを始められない | （生き物はダッシュしない） |
     | W/A/S/D | その人の W/A/S/D（カメラ基準）で歩けない。プレイヤー自身に付いた禁止と同じ意味で、ブロックの世界の方角ではない | 向きを自由に変えられるので1つだけでは道を変えない。4つ全部ならそのマスから歩き出さない |
     | 登る | 登り始められない | 登らない |
     | 投げる | 「投げる」の届き方が使えない（触るだけ。渡すときも触る） | 木の実を投げない |
     | 重い・浮く・泳ぐ | 効かせない（持っているだけの性質で、床に立っている間は水・落下・重さの板の判定に関わらない） | 同じ |

   - 詰み防止: W/A/S/D のどれか1つの禁止なら、ほかの向きで降りられる。4つ全部が禁止のブロックの上でも、跳ぶ（ジャンプ禁止が無ければ）か、足もとのブロックを狙って F で禁止を回収すれば出られる。ジャンプも含めて全部禁止なら F の回収か全員リセット（リセットで戻れる詰みはそのままでよい、2026-11-21 本人）。
   - 知らせ: 禁止で押した行動ができなかったら、毎回禁止の音を鳴らし、文字の知らせは行動ごとに最初の一度だけ出す（`GameWorld._on_floor_ban_refused`）。W/A/S/D は押し始めに一度だけ鳴らす。
   - 通信: 自分のアバターは自分の画面で動かす（ADR 0006）ので、参加者の画面が、受け取った台帳とブロックの位置で足もとの禁止を判断する。跳んでからホストに戻されることはない。生き物はホストが判断する。
   - 記録した解き方への影響（全ステージの関所・通し・試遊テストを実行して確かめた）: 変わったのは「遠征」（long_expedition）の
     2つの通し（ブーツと生き物・協力のジャンプ×2）だけ。上の段（5）から物見（7）へ跳ぶとき、札（ジャンプ禁止）の付いた窪みの
     ブロックの上から跳んでいたので跳べなくなった。地形は変えず、通しの手順を「ブロックの手前の地形の縁から跳んで、ブロックの
     上を越える」に直した（どちらも届く）。札の意図（このブロックは持ち上げ台として使えない）はむしろ強まった。
     ほかの関所・解き方は変わっていない。
   - 未決（本人へ）: ダッシュは「始めるとき足もとが禁止なら不可」にした。空中ダッシュは足もとが無いので効かない。ブロックの上のブロックへ禁止を伝えるかは決めていない（伝えていない）。ホットバーのジャンプの枠を「乗っている間は使えない」表示にするかは未着手。
8. **島の地面には厚さがある**（2026-11-21 本人の試遊「なんで床抜けるもん。浮島の地面一段しかないからめっちゃすぐ抜けるしな。床抜けるのマジでうざすぎる」。`src/game/terrain_grid.gd`・`terrain_mesher.gd`）。
   - 原因（ヘッドレスで再現: `tests/integration/test_solid_floor.gd`）: 地図（IslandMap）の高さ 0 の地面は y = -1 の1段だけだった。セルに能力を渡すと地形から抜けて動くブロックになり、跳ぶ・1マス動く・範囲で円ごと跳ぶと、その跡から島の下の空が見えた。物理では見えない岩盤が1段下にあって落ちはしなかったが、見た目は底なしの穴だった。さらに、地面に範囲で W/A/S/D を繰り返しで渡すと、島の縁に面したセルから列ごとに島の外へ落ちていき、穴が広がった（決定 6 で止まった）。
   - 決定: いちばん下のセルが y = -1 以下の列（島の地面）の下に、**見える土台を 3 段**（`FOUNDATION_DEPTH`）置く。地面の島は 4 段の厚さに見える。上面・縁の高さ・窪み（pit）・ゴールの窪み・島のあいだの谷は変えない（土台は今までの一番下のセルより下にだけ足す）。持ち上げ台の窪みのブロックは今までどおり窪みの床に止まる。風・水の範囲は地形の箱（`terrain_boxes`）から作るので、ずれない。
   - **土台は能力を渡せない**（セルではない。狙っても照準は付かない）。能力を渡せるのは今までのセルだけ（どの島でも渡せるセルは1つも増減していない）。理由: (1) 記録した解き方・関所はどれも「どのセルが動くか」に依存していて、それを変えずに済む。(2) 高さ 0 の地面の窪みは深さ 1 で止まり、自分のジャンプ（1.3）で必ず出られる（2 段の窪みにすると、ジャンプを貸した後に出られない）。(3) 窪みを狙って範囲で渡しても、地下の円（数十のセル）が動くブロックにならない。高い列（崖）の下のセルは今までどおり渡せるので、崖を掘る・押し出す解き方は変わらない。
   - 宙に浮いた列（いちばん下のセルが y = 0 以上。台座・広場の壁など）は今までどおり、見えない岩盤 1 段だけ（形を変えない）。
   - 見た目: 土台の上の段は表のセルに合わせた土・砂・岩の色、下の段は濃い岩、島の底の面は暗くする。表のセルは土台を「となり」とみなすので、境目に溝ができない。抜けた跡には土台の上面（土の床）を描く。
   - 性能: 土台の当たり判定は、同じ高さの範囲で東西に続く列を1つの箱にまとめる（今までの岩盤と同じ数）。見た目は変わらないので、組み立てるときに一度だけ作る（セルが抜けるたびの作り直しは表のメッシュと窪みの床だけ）。

## 採らなかった案

- **RigidBody3D のブロック**: 隣接ブロックとの摩擦・積み重ねの揺れで、ルールどおりの「1回のジャンプ」「1ブロックの移動」が読みにくくなる。パズルとして予測できる動きを優先した。
- **CharacterBody3D のブロック**: キネマティック同士は押し合わないため、乗っているプレイヤーにぶつかって上昇が止まる。
- **連結した隣接ブロックを一体の剛体にする**: 本人が明確に不採用とした（コンセプトノート 2026-11-17）。決定 6 の組は「同時に動かす」だけで、この案とは違う。
- **組の一部の列だけ進める（列ごとの鎖）**（決定 6）: 2×2 の片方の列だけ塞がれると形が崩れ、「一緒に動いてほしい」に反する。地面の円でも、縁に面した列だけが少しずつ島の外へ流れる。
- **違う付与でも、同時に押したら組にする**（決定 6）: 依頼の指示（違う付与は今までどおり別々）に合わせた。本人が望めば `WorldTicks.fire_single_shots` の組の作り方を変えるだけで広げられる。
- **島の土台も能力を渡せるセルにする**（決定 8）: 窪みが深くなり（自分で出られない）、範囲で地下の円まで動く。1段だけ渡せる案も、高さ 0 の地面で深さ 2 の窪みができるので採らなかった。
- **土台を地図（IslandMap._box）で足す**（決定 8）: ステージの定義の箱（風・水の検査に使う）が変わり、広場・導入ステージ・試作の島など地図を使わない地形に効かない。地形を組み立てるところ（TerrainGrid）で足した。

## 見直し条件

- Windows 実機で、乗車中の振動・すり抜けが目立つ（ヘッドレスの固定 60fps では未発生）。
- 生き物を入れる P1 で、ブロックと生き物の押し合いが必要になったとき（横方向の外力を設計し直す）。
