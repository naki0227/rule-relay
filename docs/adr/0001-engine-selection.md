# ADR 0001: ゲームエンジンに Godot 4.6 系＋型付き GDScript を採用する

- 状態: 採用（2026-11-18）。見直し条件あり
- 決定者: 本人の開発方針「第一候補は Godot 4.6 系＋型付き GDScript」を前提に、Claude が比較して推奨
- 固定バージョン: Godot **4.6.3-stable**（2026-11-18 時点の 4.6 系最新パッチ。公式リリースの SHA-512 を検証）

## 背景

3D三人称の箱庭パズル。能力トークンの所有・禁止の優先・単発の成功判定など、ルールの厳密さが体験の中心になる。
動く足場に乗る、隣接していても一体化しないブロック、願いで動く生き物が必要。
提出期限は 2027-03-15 23:59 で、Windows 11 の実行ファイルが要る。開発は個人で、残りは約4か月。

## 比較（2026-11 時点。各項目は一般的な特性で、本作での実測は P0 で行う）

| 観点 | Godot 4.6 | Unity 6 |
|---|---|---|
| 3D物理 | Jolt Physics を統合（4.6 の新規プロジェクトでは既定）。CharacterBody3D の床判定・段差処理は自前の調整が要る | PhysX。CharacterController・Rigidbody の実績と情報量が多い |
| 動く足場 | AnimatableBody3D を動かすと速度が物理側に伝わり、CharacterBody3D は床の速度を引き継ぐ | Kinematic Rigidbody＋親子付けや速度加算。定石は多いが自前実装 |
| 生き物 | NavigationServer3D、AnimationTree。FSM は GDScript で軽く書ける | NavMesh、Animator、AI 資産が豊富 |
| テスト | 公式の単体テスト基盤はない（GUT・gdUnit4 はサードパーティ）。ルールを純粋なクラスに分ければ自前の小さなランナーで十分 | Unity Test Framework（NUnit）が公式。Edit/Play Mode テスト |
| CI | エディタ約140MB、ライセンス不要。`--headless` でインポート・テスト・エクスポートまで Linux で完結 | エディタイメージが数GB。CI でのライセンス認証（シークレット管理）が要る。GameCI に依存 |
| Windows ビルド | Linux から Windows 用 exe を出力できる（PCK 埋め込みの単一 exe） | Mono なら Linux から可。IL2CPP は Windows ホストが必要 |
| 開発期間・規模 | 起動・反復が速い。テキスト形式のシーンで差分レビューがしやすい。3D の資産やツールは少ない | 機能・資産は最も多いが、プロジェクトが重く、YAML シーンの差分は読みにくい |
| ライセンス | MIT。ランタイム料金なし | Unity Personal は売上条件付き無料。規約変更の履歴あり |
| Blender 連携 | `.glb` を標準でインポート。`.blend` の直接インポートも可 | FBX が中心。`.glb` は追加パッケージ |

## 決定

Godot 4.6.3 と型付き GDScript を採用する。物理は Jolt を明示する（`project.godot` の `physics/3d/physics_engine`）。

### 採用理由

1. **CI と Windows ビルドを Linux 上で完結できる**。ライセンスのシークレットが要らず、公開・非公開を問わずクリーン環境で再現できる（P0-0 の判定基準）。
2. **ルールの厳密さを単体テストで守れる**。ルールは `RefCounted` の純粋クラスにし、物理やノードに依存させない。
3. **動く足場に乗る挙動**が AnimatableBody3D と CharacterBody3D の組み合わせで標準的に作れる。
4. 軽量で反復が速い。シーンと設定がテキストなので、AI と人の両方で差分をレビューしやすい。
5. `.glb` を標準で受け取れ、Blender を中心にした制作方針と合う。

### 欠点・リスク

- 3D の情報・資産・ミドルウェアが Unity より少ない。生き物のアニメーションや演出は自作の比重が大きい。
- CharacterBody3D の段差補助・床の追従は調整が要る（段差 0.4 ブロックの補助は自前実装）。
- 公式テスト基盤がないため、テストランナーを自前で保守する（docs/adr/0002）。
- GDScript の型検査はエンジン付属のパーサー頼み。警告の一部をエラーへ格上げして補う。
- 署名していない Windows exe は SmartScreen 警告が出る（Unity でも同じ）。提出説明書に起動手順を書く。

## 見直し条件

次のいずれかが起きたら、エンジン継続を本人と再判断する。乗り換えの費用が膨らむため、判断期限は **P0-2 完了時（目安 2026-12 中旬）** とする。

- 動く足場への乗車・段差補助・独立ブロックの同時ジャンプで、Jolt の挙動が許容できないほど不安定（すり抜け、乗り物から振り落とされる）で、回避に1週間以上かかる。
- Windows 11 の想定ハードで、P0-3 の島が 60fps を大きく下回り、最適化で解決しない。
- 必須の機能が Unity のミドルウェアでしか実現できないと分かった。
- Godot 4.6 系に、本作に影響する重大な不具合が見つかり、パッチで直らない（その場合はまず 4.6 系の別パッチを検討）。
