# ADR 0009: ステージの定義とクリア条件

- 状態: 採用（2026-11-20。ステージのデータとルールだけ。ステージを組み立てる実行時の層・ハブの歩き回り・報酬は対象外）
- 出典: `docs/handoff/2026-11-20-multiplayer-handoff.md` 2-3・2-6〜2-8・3.1・6、受け入れ 10・17（クリア条件）・23

## 決定

1. **ステージはコードで組み立てる純粋なデータ（`StageDef`、RefCounted）にする。** `.tres` は使わない。ノードを作らないので、ルールの単体テストで定義・配置・解けるかの目安を確かめられる。実行時の層は `StageDef` を読んで地形・ブロック・鐘・生き物のノードを作る。
2. **地形は新しく作らず、`PrototypeIsland.terrain_boxes()` と同じ形式**（`[Vector3i 最小, Vector3i 最大, 種類]`、上面 = 最大の y + 1）にする。`TerrainBuilder.add_box` でそのまま作れる。
3. **能力・禁止の置き方を3つに分ける。**
   - 固定: ブロック・生き物に最初から付いたトークン（`TokenSpec`）と世界に落ちている器（`world_items`）
   - 開始時の手持ち: 参加順ごとのホットバー（`loadouts`）と、全員の手元に置く禁止（`prohibitions`。通常インベントリにあっても効く）
   - 人数別補助: `helpers`（参加人数 → `PlacementSpec` の配列）。世界の器か、ブロックに付いた状態で置く。人数ごとの数はステージが決め、共通式（「ジャンプ合計4個」など）は作らない（引き継ぎ仕様 2-6）
4. **クリア条件は `ClearCondition` の4種類**: `REACH_HEIGHT`（操作中の誰かが範囲の上で高さ以上）、`ALL_AT_GOAL`（操作中の全員がゴールの箱の中）、`CARRY_OBJECT`（key の物体が箱の中）、`ACTIVATE`（key の仕掛けが作動）。判定は辞書のスナップショット（`positions` / `active` / `entities` / `activated`）だけを見るので物理なしで試せる。結果だけを見て、手順は強制しない（2-5）。
5. **補助の作り直し（`StageLoadout.rebuild_helpers`）は、前回置いた補助のトークン ID を覚えておき、トークンごと消してから置き直す。** トークンと一緒に器（出自）も消すので、世界・ブロック（範囲付与を含む）・仲間の手元・器の中・束ねた中のどこにあっても一度で消え、複製も取り残しも出ない。呼ぶのは全員リセットのときだけ（2-7）。4人目が入っても、その場では何もしない。
6. **トークンの削除は `RuleLedger` に足さず、新しい `TokenRemoval` が公開済みの `snapshot()` → 取り除く → `restore()` で行う。** `RuleLedger` の公開メソッドは gdlint の上限 45 に達している。読み取り専用のメソッドを外へ移す案は呼び出し元（`GameWorld` など）を書き換えることになり、並行して進んでいる作業と衝突しやすい。`restore()` は台帳の `RuleToken` / `RuleVessel` を作り直すが、作り直しは全員リセット（直前に台帳ごと restore する）とクリア後にしか起きないので、新たに古い参照が生まれる場面はない。消した ID は再利用しない（採番の続きを保つ）。
7. **クリア後（`StageLoadout.end_stage`）はステージのトークン・器・ブロックや生き物の登録をすべて消し、プレイヤーの登録と参加中の印だけを残す。** 能力をステージの外へ持ち出せない（2-8、受け入れ 23）。個人の永久報酬は別の仕組みで扱う。
8. **補助のトークン ID はチェックポイントと一緒に保存する**（`capture_state()` / `restore_state()`）。全員リセットでは、台帳と補助の記録を同じチェックポイントへ戻してから、いまの人数で `rebuild_helpers` を呼ぶ。
9. **ブロック・生き物の entity_id は実行時の層が登録して `key → entity_id` で渡す。** ノードを作らない検証用に `StageLoadout.register_entities` を用意した（番号の振り方は `GameWorld` と同じ 100〜 / 500〜。一致はテストで確かめる）。

## 仮にしたこと（本人の判断待ち・プレイテストで見直す）

| 項目 | いまの扱い | 理由 |
|---|---|---|
| 全ステージの配置・寸法 | すべて仮（`StageDef.provisional = true`） | 引き継ぎ仕様 6・7-9 で具体レイアウトは未決 |
| `ALL_AT_GOAL` で必要な人 | 操作中（生きている）正式参加者だけ。死亡観戦中の人の到達は要らない。誰も生きていなければ成立しない | 5.1「条件成立後は死亡観戦中の人もクリア」から、生きている人だけで達成できる形にした。全滅時の扱いは 4.1 で未決 |
| 通信切断中の人 | `active` に入れるかは実行時の層が決める（ここでは決めない） | 切断猶予が未決（4.3・7-1） |
| `REACH_HEIGHT` の誤差 | 足もとが高さ − 0.05 以上 | 物理で少し沈むため。調整値 |
| 導入 `intro_jump_lend` | 地面（0）→ 小段差（1、自分で跳べる・横を回れる）→ 岩棚（2、跳べない）。岩棚の手前の窪みにブロック（上面 0）。ジャンプを渡して乗ると 2.5 持ち上がって岩棚へ。人数別補助なし。手持ちは W/A/S/D・ジャンプ（投げるなし = 触って渡す） | 6 の提案どおり。地面から降りないので、渡した後もブロックへ戻って F で回収でき詰まない。ブロックの上面を地面と同じにしたのは、地形が1mの箱なので低い斜面を作れないため |
| 導入の2〜4人の別解 | ジャンプを1人に集めて自分で跳ぶ（×2 で 2.6 > 2 の想定）、1人が乗りもう1人が渡す など | ジャンプ×n の物理上の高さは未決（7-8）。線形と仮定したときの目安 |
| `relay_carry` | 誰もジャンプを持たずに始め、段（高さ 1）の上に全員が入るとクリア。ジャンプは補助として世界に置く: 1人 1個・2人 1個・3人 1個・4人 2個。台ブロックを昇降機にする別解もある | 受け渡しで回すと全員上がれる。人数ごとの数は仮 |
| `bell_valley` | 全員ジャンプ禁止（ステージの禁止）。底なしの谷（幅 4）の向こうの鐘を、岸の発射台に「投げる」を渡して鳴らす（`ACTIVATE "valley_bell"`）。人数別補助なし | 岸から触れる距離の外に鐘を置いた。発射台と鐘の距離は試作島と同程度（6 マス） |
| ハブ | 平らな広場と3つの入口（入口の箱に入るとそのステージ）。手持ちは W/A/S/D・ジャンプ | 2-2。入り方の UI・にぎやかさの演出は未決 |
| 開始ホットバーが人数より少ないとき | 最後の要素を使う（`set_loadout_for_all` は1つだけ持つ） | 参加順で手持ちを変えるステージを作れるようにした |
| 途中合流した人の開始手持ち | `give_start` を用意したが、呼ぶ場面は実行時の層が決める | 全員リセットでの「初期配分の再構成」（2-7）の細部は未決 |

## 採らなかった案

- **`RuleToken` に「補助」の印（タグ）を足す**: スナップショット形式とネットワーク同期の両方に手が入る。補助かどうかはステージの事情なので、ステージ側が ID を覚える方が台帳を汚さない。
- **`RuleLedger.remove_token` を足し、代わりに読み取り専用のメソッドを `PartyQuery` へ移す**: 呼び出し元の書き換えが並行作業と衝突しやすい。削除は全員リセットとクリア後だけなので、snapshot/restore で十分。
- **人数が変わった瞬間に補助を足し引きする**: 本人確定（2-7）に反する。
- **ステージを `.tres` リソースにする**: 型付きの内側クラスと人数別の辞書を手で書くより、コードの方がテストと差分が読みやすい。
