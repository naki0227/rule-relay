# ADR 0020: 広場へ戻るときは入ったポータルの前に立ち、ステージの目的を画面の隅に出し、一時停止のメニューを作り直す

- 状態: 採用（2026-11-21）
- 番号: 0018・0019 はほかのブランチが使う予定なので 0020 にした
- きっかけ（本人の言葉）:
  - 「ステージクリア後とかステージ出た後は、入ったステージの前に出てほしい」
  - 「ステージに入った後に、どうすればゴールなのかみたいな、そういう目的の表示とかも全然ないから、鐘鳴らさなあかんとかも、
    ゴール行けばいいだけかなとかなったりして、よくわからなくなる」
  - メニューの「島のはじめから」の説明「保存をすべて消して…」は保存データが消えるように読めて怖い。ステージの中のメニューに
    置くものでもない。ステージから出る方法が無い。2 種類のやり直し（チェックポイントへ・ひとつ前の保存へ）は分かりにくく要らない
- 決めた人: 本人（ポータルの前に戻る・目的の一覧・メニューの項目と文言）。立ち位置の探し方・数値・協力中の決め方・画面の形は
  AI の判断（仮）
- 関連: ADR 0007（全員リセット）、0008（進行と報酬）、0009（クリア条件）、0010（進行役）、0013（広場とポータル）

## 決定

1. **広場へ戻ると、入ったステージのポータルの前に立つ**（`PortalReturn`。`PartyDirector` が持つ）。
   - クリア（お祝いと報酬の知らせの `RETURN_DELAY` 4 秒の後）・メニューの「このステージから出る」・その投票のどれで
     戻っても同じ。広場で落ちたとき・戻った後に部屋へ入ってきた人も、同じ立ち位置に置く。広場の中で入り直したときは
     今までどおり出現地点。
   - 立ち位置（`PortalSpots`。`Overworld.build` がポータルごとに決める）: 4 人分の足もとが全部ポータルと同じ高さの地面で、
     まわり 0.35 m も地面（縁で落ちない）、壁・ブロックにかからず、どの入口の箱（0.45 m 広げた箱）の外。
     ポータルの正面の先 → 斜め前 → 横 → 斜め後ろ → 後ろの順に、きょり 3〜5 m で探す。並びは出現地点と同じ 1 m おきの
     横一列（協力中は 1 人ずつ別の場所。重ならない）、狭いところは 2 列。その先 3 m にも地面がある向きを先に選ぶ
     （崖の縁に向かって立たない）。いまの 57 のポータルでは 31 が正面の先、残りは正面の先が谷・庭の壁・隣のポータルなので
     横や斜め。
   - 向き: ポータルから立ち位置への向き（ポータルに背を向けて広場の側を見る）。体とカメラの両方を向ける。協力中は
     ホストが決め、参加者の画面へは位置と一緒に向きを送る（`_moved(at, yaw)`）。
   - 広場が育っても（建物・住む生き物）立ち位置は変わらない。建物・置物は当たり判定が無いので、ポータルの場所と向きと
     地形だけで決まる。
   - **すぐ入り直さない**: 立ち位置は入口の箱の外なので、F を押しただけでは入らない。加えて、戻ってから
     `PortalReturn.GRACE`（1.5 秒）は、戻ったポータルの F を受け付けない（クリアの直後の連打で入り直さない）。
     ほかのポータルはすぐ使える。自由な遊びを止めるルールにはしない（1.5 秒・そのポータルだけ）。
2. **最後に入ったステージを進行に保存し、次の起動もそのポータルの前から始める**（`PlayerProgress.last_portal`。
   ステージに入ったときに保存）。今の設計に合う理由: 初めての人は保存が無いので出現地点（導入のポータルの真正面。
   `docs/onboarding.md`）のまま。2 回目からは続きの場所から始められる。ポータルが閉じていれば（製品版の開き方に
   切り替えたなど）出現地点。協力中はホストの進行で決まる（広場と同じ。ADR 0013）。古い保存には無い項目なので、
   無ければ空として読む（版は上げない）。
3. **一時停止のメニュー（`PauseMenu`）を作り直した**。
   - ステージの中: 「つづける」「チェックポイントからやり直す」「このステージを最初から」「このステージから出る」
     「せってい」「ゲームをやめる」。広場: 「つづける」「せってい」「ゲームをやめる」だけ。
   - 「チェックポイントからやり直す」は、これまでの「チェックポイントへもどる」と「ひとつ前の保存へもどる」をまとめた
     もの（中身は全員リセット＝V 長押しと同じ投票。ひとりなら 1 票で決まる）。ステージ（`StageWorld`）では 2 つとも
     もともと同じ投票だった。「ひとつ前」の項目は消したが、`restore_previous_checkpoint` はテスト
     （`test_checkpoint_softlock`・試作の島の保存の履歴）が使うので呼び口を残した。
   - 「このステージを最初から」: 説明は「このステージに入ったときの状態から、やり直します。」。保存を消すとは書かない。
     もう一度えらぶと確定（「もう一度えらぶと、このステージを最初から」）。同じステージを新しい回として作り直すだけで、
     進行（クリア・報酬・広場の育ち具合・最後に入ったポータル）には触らない（`enter_stage` は進行を書き換えず、報酬は
     クリアのときだけ配るため）。`test_pause_menu_stage` で、メモリの進行と保存したファイルの両方が変わらないことを確かめる。
   - 「このステージから出る」: もう一度えらぶと、広場の、このステージのポータルの前へ（1.）。
   - 協力中の決め方（`StageLeaveVote`。「最初から」と「出る」で同じ）: **ホストがえらぶと、投票なしで全員で行う。
     参加者がえらぶと投票が開く**（母数・過半数・30 秒の時間切れは全員リセットの投票と同じ。知らせは全員の画面に出す）。
     ホストがえらんでも決まる。開いている投票と違う方をえらぶと、新しい投票に置き換える（足し合わせない）。
     ホストは状態を持つ権威なので「ホストが決める」は今の作りに一番素直で、参加者は投票で頼める。
   - 「保存 n / m」の数は消した。ステージではチェックポイントの保存の履歴を使っていない（チェックポイントはチーム共通の
     1 つ）ので、いつも「保存 0 / 3」と出ていて、遊ぶ人には意味が無かった。
   - V 長押しの案内・投票の知らせ・キー割り当ての名前を、新しい言い方「チェックポイントからやり直す（投票）」にそろえた
     （`PartyDirector.RESET_VOTE_TITLE`）。戻る先は最後のチェックポイント（無ければステージに入ったとき）。
4. **ステージの目的の一覧**（`StageObjectives`・`ObjectivePanel`）。
   - クリア条件（`ClearCondition`）の木を葉に分け、同じ種類・同じ文の葉を 1 行にまとめる。順はどうぶつ → 運ぶ物 → 鐘 →
     時の鐘 → 高い所 → ゴール。文は「どうぶつを巣へ」「ブロックを運ぶ」「鐘を鳴らす」「時の鐘を鳴らす」「高い所へのぼる」
     「全員でゴールへ」（ひとりなら「ゴールへ」）。2 つ以上要るときだけ「1/3」のように数を出す。
   - 種類だけでは伝わらない条件には `ClearCondition.objective_text` を付ける（`titled("…")`）。今は砦跡の要石
     （「要石を窪みへ」）だけ。全ステージで空の行・仮の文・内部の名前が出ないことをテストで確かめる。
   - 進み具合はホストがクリアの判定と同じ材料（`clear_snapshot`）で数え、party の配信で参加者へ送る。参加者は数えない。
     ゴールは「生きている人のうちゴールにいる人 / 生きている人」。
   - 画面: ステージに入ると上の真ん中に大きく 3 秒出し（「このステージの目的」・「順番は自由」）、右上の隅へ縮む。
     隅の札は行ごとに印・短い文・チェック（まだは細い輪、そろうと若葉色の丸に白いチェックで、少し弾む）。
     目的を見るキー（Tab。`show_objectives`）と、一時停止のメニュー（メニューの札の右）で、もう一度大きく出る。
     パッドには既定のボタンを割り当てない（空いているボタンが無く、L スティック押し込みはキー割り当ての入れ替えの
     テストが空きボタンとして使う。Start のメニューで見られ、「せってい」で割り当てられる）。
     広場・持ち物を開いている間は出さない。書体・色・札は今のもの（`UiTheme`）。HUD（`hud.gd`）は変えずに、GameRoot が
     HUD に足す。
   - 一覧は表示だけで、クリアの判定も順番も変えない（「ルールは厳格に。解法は自由に。」）。

## 採らなかった案

- **ポータルの正面に決まったずれで立たせる**: 57 のうち 26 のポータルで、正面の先が谷・庭の壁・隣のポータルの入口だった。
- **ポータルの箱から一度出るまで入れない（人ごとの見張り）**: 入るには箱の中で F が要り、立ち位置は箱の外なので、
  見張りを足しても変わらない。連打だけ短い待ちで防ぐ。
- **クリアの後すぐ広場へ戻す**: お祝いと報酬の知らせ（`RETURN_DELAY`）を残す指示。
- **「出る」「最初から」をホストも含めて全員の投票にする**（途中の版）: 本人の指示は「ホストが出たら全員」。ホストまで
  投票にすると、ひとりで遊ぶのと同じ操作が協力中だけ急に遅くなる。参加者からは投票で頼めるので、勝手に消える不満は小さい。
- **参加者の「出る」をホストへの問い合わせ（はい・いいえの窓）にする**: 新しい画面が要る。すでにある投票と知らせの仕組みを
  使う方が単純。
- **協力中の「最初から」を、これまでどおりチェックポイントへの投票にする**: 項目の名前と中身がずれる（本人が混乱した原因）。
- **参加者が自分の画面で進み具合を数える**: 鐘・物の位置・ゴールの人数は参加者にも届いているが、届く順がずれると
  一瞬だけ画面が食い違う。数はいくつかの整数なので、ホストが数えて配る方が単純で全員の画面がそろう。
- **目的をずっと大きく出す・3D の文字で出す**: 本人は画面のごちゃごちゃを嫌う。入ったときだけ大きく、あとは隅に小さく。

## まだやっていないこと・仮の点

- 数値はすべて仮: 入り直さない 1.5 秒、大きく出す 3 秒、立ち位置のきょり 3〜5 m・先の地面 3 m、投票の 30 秒。
- 横や斜めに立つポータル（26）は、正面の先の地形を広げればまっすぐ前に立てる。地方の形を直すときに見直す。
- 印は描いた記号（どうぶつの顔・箱・鐘・時計つきの鐘・矢印・旗）。世界観の絵柄が決まったら差し替える。
- 「出る」「最初から」の投票は HUD の上の札（`PartyBanner`）には出していない（全員の画面への知らせだけ）。
- 画面: `docs/images/ux/objectives-big.png`（入った直後）、`objectives-corner.png`（途中・鐘を鳴らした後）、
  `portal-return.png`（戻った直後のゲームの画面）、`portal-return-look.png`（振り返ってポータルを見た画面）、
  `pause-menu-stage.png`（ステージの中の一時停止のメニュー）。lavapipe での描画（`tools/capture_objectives_ux.gd`）。
