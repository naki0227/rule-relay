# ADR 0008: 個人の進行・クリア報酬・保存

- 状態: 採用（2026-11-20、P5 の純粋なルールとローカル保存の部分。通信・ハブの見た目・ホスト移譲の実装は対象外）
- 出典: `docs/handoff/2026-11-20-multiplayer-handoff.md` 5.1〜5.3・9 の 17〜22、`docs/adr/0006-online-co-op-transport.md`（2026-11-20 本人と合意）

## 決定

1. **進行は各プレイヤーの手元に、プレイヤーごとに持つ**（`PlayerProgress`）。ホストだけのハブが育つ案は撤回済み（5.1【確定】）。ルームで見えるハブの世界の状態とは別のデータにする（5.3）。保存先は各自の PC の `user://progress/<profile>.json`（`ProgressStore`）。Steam 版ではこのファイルを Steam クラウドの同期対象にする（ADR 0006 の 4）。
2. **報酬はホストの台帳（`StageRunRewards`）が「誰に出すか」だけを決め、何を渡すかは受け手の `PlayerProgress` が自分の進行から決める。** 同じクリアでも、初めての人には初回報酬、2回目の人には記録と条件の報酬になるため。ホストは各自の進行を持たない（ADR 0006 の 4）。
3. **報酬の資格は 5.2 の真理値表どおり。** クリア成立時の状態を `Status` で受け取る:

   | 状態 | 報酬 |
   |---|---|
   | `ACTIVE`（正式参加・生存） | 付与 |
   | `DEAD_SPECTATING`（正式参加・死亡観戦） | 付与 |
   | `DISCONNECTED`（正式参加・意図しない切断） | 付与。再接続時に配達 |
   | `WAITING_SPECTATOR`（途中入室・操作参加前） | 対象外 |
   | `LEFT_BEFORE_CLEAR`（クリア前に明示的に退出） | 対象外 |
   | `LEFT_AFTER_CLEAR`（クリア後に退出） | 維持。取り消さない |

   ステージ固有のクリア条件（「全員到達」など）の判定はステージ側の責務で、台帳はクリアが成立した後だけを扱う。
4. **冪等**: 報酬イベントの ID は `stage_run_id/player_key` で決まる。受け手は適用済みの ID を保存し、同じ ID は無視して受け取りの返事（ack）だけ返す。ホストの再送・ホスト移譲後の再送・再接続時の再配達で二重に付与しない。台帳の `settle` も走行1回につき1度だけ。
5. **配達**: ack が来るまで配達待ち。`events_to_send(接続中の key)` はクリア直後と再接続時に呼び、ack が来るまで同じイベントを返す。
6. **初回と周回**: 初回クリアでだけ新エリア・ハブの発展・初回報酬を渡す（初回クリアの時刻も残す）。2回目以降は記録の更新・特殊条件・収集品だけで、初回の物は二度と渡さない。古い走行の報酬が新しい走行より後に届いても、それは周回として扱う。
7. **記録は項目ごとに別々**に持つ（最速クリア秒・最少能力使用・最少受け渡し）。各記録には、その記録を出した走行の参加人数と stage_run_id を添える。クリアした参加人数は別の集合として持つ。1つの総合スコアは作らない（5.1【確定】）。
8. **報酬の種類は見た目・記録・収集だけ**。報酬表（`RewardTable`）に恒久的な能力強化を書いても `errors()` で拒否し、渡さない（5.1【提案】に従う）。
9. **保存**: 一時ファイルに書いてから名前を変えて置き換える。先頭に `schema_version`（いまは 1）。ファイルが無ければ新しい進行（`ERR_FILE_NOT_FOUND`）、壊れていれば新しい進行と `ERR_FILE_CORRUPT`、知らない新しい版なら `ERR_FILE_UNRECOGNIZED` を返し、止まらない。壊れたファイル・新しすぎる版のファイルは `<profile>.corrupt.json` へ退避し、次の保存で失わない。プロファイル名は英小文字・数字・`_`・`-` だけ（パスの外へ出させない）。
10. **台帳は `to_dict` / `from_dict` で新ホストへ渡せる**。復元後もイベントは同じ規則で作り直すので ID は変わらない。

## 保証の範囲（ADR 0006 の 5、本人合意）

- 切断した正式参加者の報酬は、**部屋が残っている間に戻れば受け取れる**。ホストは台帳を保持し、再接続時に配達する。
- 全員が抜けて部屋が消えた後に戻った人へは届かない。届けるには報酬の記録だけを置く小さなサーバーが要る。必要になったら足す。「参加したら必ず無期限に報酬」という保証はしない（5.2 の注記）。
- ホスト移譲中の台帳の引き継ぎは、`to_dict` を状態の配布に含めれば成立する形にした。実際の配布と移譲は P5 の通信側で実装する（未実装）。

## 仮にした挙動（本人の判断待ち）

| 項目 | いまの挙動 | 理由・根拠 |
|---|---|---|
| 報酬の中身 | `RewardTable.provisional()`。ステージは `prototype_island` だけ。ID はすべて `tmp_` で始まる仮（新エリア1・ハブ発展2・衣装1・条件2・収集品2） | 5.1【提案】・7-10 で未決 |
| 特殊条件 | 走行指標の上限（`at_most`）だけで表す。初回クリアでも満たせば渡す。各条件は一度だけ | 条件の内容は 7-10 で未決。初回でも満たした事実は同じなので分けなかった |
| 収集品 | 走行中に拾った ID のうち、表にあるものだけを何回目のクリアでも渡す | 5.1「追加収集品を狙える」 |
| 計測の定義 | 秒はステージ開始からクリアまで（一時停止・移譲中を含むか未決）。能力使用は発動・付与の回数、受け渡しはプレイヤー間の譲渡の回数。数えるのはホスト | 7-10 で未決 |
| 参加人数 | 報酬対象（`ACTIVE`・`DEAD_SPECTATING`・`DISCONNECTED`）の人数。待機観戦とクリア前退出は数えない | 5.2 の資格と同じ境界にした |
| 同じ値の記録 | 先の記録を残す | 先に出した人の記録を後から奪わない |
| クリア時刻 | ホストの時計の UNIX 秒 | 時計のずれ・改ざん対策は 7-11 で未決 |
| 適用済みイベント ID | 消さずに全部保存する | 1 件数十バイトで、周回しても十分小さい。上限が要るなら後で古い走行から間引く |
| player key | 再接続しても変わる peer ID ではなく、公開の安定した識別子を前提にする。ENet 版の秘密の `session_key` はイベントに載せない | `session_key` を知ればその人として入れる（`PartyRoster`）ので、他の参加者へ配るデータに入れない。ENet 版での公開 ID の決め方は通信側で決める |

## 確かめていないこと

- Windows で `DirAccess.rename_absolute` が既存ファイルを置き換えられるか（Linux の CI でだけ確認した）。Windows 11 実機で確かめる。
- Steam クラウドの同期と、オフラインで遊んだ後の競合（7-11 で未決）。
- アプリの強制終了で切断を装う場合の区別（5.2 の注記で未決）。いまは呼び出し側が渡した状態をそのまま信じる。

## 採らなかった案

- **ホストが全員の進行を持ち、結果を配る**: 各自の初回／周回の判断にホストが他人の進行を知る必要があり、ADR 0006 の「各自の手元に保存」と合わない。
- **報酬の中身をホストが決めてイベントに入れる**: 受け手が初回か周回かをホストは知らないので、初回の物を重ねて渡すか渡し損ねる。
- **総合スコアを1つ持つ**: 5.1【確定】で否定。
- **壊れた保存を黙って新規で上書き**: 一時的な読み込み失敗で進行を失うので、退避してから新規にした。
