原因は大きく3つだった（AI の振り返り）:

2. **音色が止まっている**: 減衰の形が決まっていて、鳴っている間に音程も明るさも動かない
3. **作り方の癖が輪郭を消していた**（測って見つけた）:
   - 2極の共鳴器が、低い周波数ほど大きく鳴る式のままだった（全部が暗く寄る）
   - 仕上げで全部の音の頭に 4ms のフェードインを掛け、叩いた瞬間を毎回弱めていた
   - 音量をそろえるとき、ピークを tanh で丸めて、当たりの山を潰していた
   - 部屋の反射を強く足し、最初の 20ms に暗い反射が流れ込んでいた
4. **量産型に聞こえる**: カリンバ・泡・ハープはカジュアルゲームの定番の音色

### 作り方（`tools/sfx/build_sfx.py`）

- **島の物そのものが楽器**: 楽器の音色を借りず、この世界にある物（木箱・石・草・紙の札・本・鐘・生き物）の材質を鳴らす
- **物理寄りの合成**: 物は材質ごとの規則でばらつかせた数十〜百のモードを持ち、叩く・こする・はじく雑音で鳴らす。
  当たった瞬間の接触音をそのまま重ねる。鳴り始めに音程がわずかに下がり、高い成分ほど早く消える。小さな部屋の反射は控えめに。
  空気のかすかな雑音（ピークの約 −54 dB）を敷いて、完全な無音を避ける
- **法則の音**: 能力ごとに音程が決まったモチーフ（W=0, A=2, S=4, D=7, ジャンプ=9, 投げる=12, 高跳び=14, 登る=16 半音）。
  ガラスの棒を指でこするような、うなりのある澄んだ音。渡す・回収するときに、その能力の音程で鳴る（`lend@9` のように鳴らす）
- **受け取った物が応える**: 能力を渡すと、受け取った物が自分の材質の声で応える（木箱の「コン」、石の「コツ」、草の地面の「ボフ」、生き物の「ぽむ」と鳴き声）
- **持ち物は紙の札と本**: 指す（札の角）、選ぶ（札を机に当てる）、決定（判を押す）、取り消し（札をすべらせて戻す）、開く・閉じる（本）、つまむ・置く（札）
- 判断した値: 机の音の木は、甲高い振動が強く出ない個体（乱数の種）を選んだ

### 2026-11-18 の見直し（「こもった音になりがち」）

本人の感想: 「こもった音になりがち」。原因は 3 つあった。

1. **基準が明るさそのものを禁止していた。** 「高い音」を防ぐつもりで、4kHz 以上 6% 未満・2〜5kHz 15% 未満・重心 1500Hz 未満にしていた。
   これは音程ではなく輪郭（叩いた瞬間の明るさ）を削る基準で、全体がこもった。重心は 250〜500Hz しかなかった。
2. **仕上げで全部の音に 4kHz のローパスを掛けていた**（残響も 2.5kHz）。当たりの雑音も 0.6〜3kHz・ごく小さい音量だった。
3. **測り方の誤り。** 音全体に Hann 窓を掛けていたので、音の頭（当たり）がほぼ 0 にされ、明るさを測れていなかった。端だけ丸める Tukey 窓に直した。

「高い音」と「こもる」は別の問題なので、**音程は主な周波数で、輪郭は叩いた瞬間の明るさで**、別々に測るようにした。
参考に Kenney の UI 効果音（CC0、51 個）を同じ方法で測ると、重心の中央値は約 3.5kHz（10〜90% で 1.7〜7kHz）。
このゲームはゆるふわなので、それより暖かい 0.8〜2.2kHz に置いた（素材は測っただけで、リポジトリには入れていない）。

## BGM（2026-11-20、`src/audio/music_player.gd`。仮の選曲）

本人の依頼「BGM を流したい」で、PR #42 の候補（`docs/sound-candidates-2026-11-20.md`）から場面ごとに1曲を取り込んだ。

| 場面 | 曲 | 候補 ID | ループの長さ | いつ鳴るか |
|---|---|---|---|---|
| タイトル | `assets/audio/music/title_1.ogg` | B5 | 37.0 秒 | タイトル画面 |
| ハブ | `assets/audio/music/hub_1.ogg` | B1 | 106.5 秒 | ハブの島（`StageCatalog.HUB_ID`） |
| 島（ステージ） | `assets/audio/music/think_1.ogg` | B3 | 84.0 秒 | ハブ以外のすべての島 |

- **仮の理由**: AI（Claude）は音を聴けないので、各場面の候補2曲のうち1番目（`_1`）を機械的に選んだ。良し悪しは本人の耳で決める。
- **差し替え方**: 候補の OGG（`art/audio/stable-audio/music/`）を `assets/audio/music/` へコピーし、`MusicPlayer.TRACKS`（場面 → ファイル）の1行を書きかえる。コピーした OGG の `.import` は、下の「ループ」の設定にする（Godot のエディターなら、ファイルを選んで「インポート」タブで Loop をオンにして再インポート）。テスト `tests/integration/test_music.gd` のファイル名も合わせる。
- **ループ**: 候補は最後を頭へクロスフェード済みの「継ぎ目なしのループ」なので、`.import` で `loop=true`・`loop_offset=0`（頭から全体を繰り返す）にした。`bpm`・`beat_count` は 0 のまま（拍数を入れると、ループの長さが拍から計算され、曲の長さとずれる）。
- **鳴らし方**:
  - Music バスで鳴らす。2つの再生枠を交互に使い、場面が変わったら 1.5 秒で入れ替える（クロスフェード）。
  - 同じ曲を頼まれても頭から鳴らし直さない（島のやり直し・全員リセット・同じ「島」の曲どうしの移動）。
  - Esc のメニュー・せってい・持ち物を開いている間は −6dB 下げる（12dB/秒でなめらかに）。一時停止中も曲は止めない。
  - 切り替えは `PartyDirector.world_changed`（島を作り直すたびに出る）に付いていく。参加者もホストから届いた島の作り直しで同じ合図を受けるので、いまいる島の曲になる。
- **音量**: 候補の音量はハブとタイトルが −16 LUFS、島が −18 LUFS（考えるのを邪魔しない）。設定の「BGM の音量」（初期値 70%）は Music バスに掛かる。
- **ヘッドレス**（CI・テスト）では、効果音と同じく実際の再生をしない（再生中に終了すると「resources still in use at exit」になるため）。どの曲にするかの判断と入れ替えの音量の動きは動く。
- 応募規約・AI 利用ガイドラインは 2026-11-20 に確認済み（生成 AI は容認。使ったツール・モデル・工程・期間を申告する。`docs/ai-usage.md`）。ガイドラインの確定版はエントリー開始後に出るので、提出前にもう一度確かめる。

## バスの並び（`src/audio/audio_buses.gd`）

```
Master ← SFX（「効果音の音量」） ← UI（−2dB）・World（0dB）
Master ← Music（「BGM の音量」）
```

- エディターのバス配置ファイル（`default_bus_layout.tres`）は使わず、起動時にコードで作る（効果音の方式に合わせた）。
- Godot は番号の大きいバスから順に混ぜるので、送り先の SFX は UI・World より前に置く。
- 音量は 0〜100% を `linear_to_db` で dB にする。0% は消音にする。

## 限界（正直に）

- **合成した AI（Claude）は音を聴けない。** 確認は測定値とスペクトログラムだけで、「それっぽさ」を人の耳では確かめていない。本人に聴いてもらい、直したい音を名前で指定してもらう。
- 実録音の素材（木を叩く・布・草）を使えば、さらに自然になる可能性が高い。CC0 の素材を使うか、Foley を録るかは、本人と相談する。
