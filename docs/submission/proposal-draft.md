## 2. 内容・面白さ

### 2.1 一言で言うと

自分の「操作」そのもの——前へ進む力、跳ぶ力、投げる力——を、**アイテムとして世界や仲間に貸し出す**パズル。
ブロックにジャンプを貸せばブロックが跳び、仲間にジャンプを集めればその仲間が高く跳ぶ。貸したあいだ、自分はその操作ができない。
ルールは厳格（能力は世界に 1 つずつしかなく、複製も消滅もしない。禁止は必ず優先される）だが、ゴールへの道は自由で、何通りもある。

### 2.2 核の仕組み【確定】

| 仕組み | 内容 | 根拠 |
|---|---|---|
| 能力は貸し借りできるアイテム | W/A/S/D・ジャンプ・投げる・ダッシュなどの操作が、1 つずつ「能力トークン」になっている。器（アイテム）から能力だけを貸し出し、器は手元に残る。トークンは世界に 1 つで、複製しない | `docs/requirements-status.md` 7、ADR 0003・0005 |
| 貸す相手 | ブロック（地形を含むどのブロックにも）・生き物・仲間。ブロックの W/A/S/D は世界の方角（W＝北）、プレイヤーはカメラから見た向き | requirements-status 4-1・4-2・5.1 |
| 範囲で貸す | 水平の円（半径 5 ブロック、縦 1 層。仮の値）の中の全ブロックへ、1 つのトークンで一度に貸す。どこからでも F で一括回収 | requirements-status 5.3 |
| 禁止 | 「ジャンプ禁止」のような禁止の札も、能力と同じように持ち運び・貸し借りできる。禁止は能力より必ず優先される（貸した単発も起動できない）。外から押されて動くことは妨げない | requirements-status 4-4、TODO（2026-11-19 本人の確定） |
| 集めると強くなる | 同じ能力を n 個持つと、ジャンプは高さ n 倍、W は速さ n 倍、投げるは射程 n 倍。上限は付けない | ADR 0011 決定 11（2026-11-20 本人） |
| 装備 | ジャンプブーツ（高跳び）・クライミンググローブ（登る）。装備中は自分に効き、外せば貸し出せる | requirements-status 7 |
| 願いを持つ生き物 | 「高いところへ行きたい」生き物は命令できない。能力を渡すと、願いに従って自分で使う。禁止は願いより優先 | requirements-status 6 |

### 2.3 3 つの発動方式【確定】

ブロックに能力を貸すとき、いつ発動するかを選ぶ（`docs/requirements-status.md` 5.2）。

| 方式 | 動き | 返り方 |
|---|---|---|
| 単発 | 対応するキーで 1 回だけ試みる。貸した直後に勝手には動かない | 起動したら、発動できなくても（禁止・塞がれている・空中）発動したのと同じ扱いで、直前に貸した人へ自動で戻る（2026-11-19 本人の確定） |
| 繰り返し | 一定の間隔で自動で試み続ける（例: W と S を交互にして往復足場） | 手で回収（F） |
| 信号 | 鐘などの音が届いているあいだだけ発動し、途絶えると休む | 手で回収（F） |

### 2.4 ゲームサイクル

```
ハブ（広場）を歩いて入口を見つける → ステージ（開けた島）に入る
  → 能力を貸す・集める・回して、島の条件を満たし、全員でゴールに集まる
  → クリア報酬（見た目・記録・収集品）を各自の PC に保存 → ハブへ戻る → 次の入口へ
```

| 段階 | 内容 | 状態・根拠 |
|---|---|---|
| ハブ | 番号のメニューではなく、広場を歩いて入口を見つける。入口は目安時間の短い順に一列 | 【確定】引き継ぎ仕様 2-2、ADR 0011 決定 1。見た目・にぎやかさの演出は【未決】 |
| ステージ | 島ごとに条件（鐘を鳴らす・要石をはめる・生き物を巣へ連れていく など）があり、加えて生きている全員がゴールに集まるとクリア | 【確定】ADR 0009・0011 決定 9 |
| 報酬 | 初回クリアで新エリア・ハブの発展・初回報酬。2 回目以降は記録の更新・特殊条件・収集品。**恒久的な能力強化は渡さない**（パズルの前提を崩さないため）。記録は項目ごと（最速・最少能力使用・最少受け渡し）で、総合スコアは作らない | 仕組みは【確定】ADR 0008。報酬の中身はすべて仮（`RewardTable.provisional()`）で【未決・本人が決める】 |
| 保存 | 進行は各自の PC に保存。協力で遊んでも、自分の進行が育つ | 【確定】ADR 0008 決定 1 |

世界観の案は `docs/worldview/`（4 案と推奨案の深掘り。状態は「提案」）にある。本人が選んだら、ここに次を書く。

- 主人公・生き物: 【未決・本人が決める】（`docs/worldview/` を参照）

### 2.6 セールスポイント（ならではの面白さ）

1. **自分の操作を手放す決断**: 貸せば世界が動き、自分は動けなくなる。「誰が・いつ・何を手放すか」が、そのまま協力の会話になる。
2. **ルールは厳格、解法は自由**【確定】: クリアは結果（島の条件と全員の到達）だけを見て、手順を強制しない（`src/stages/clear_condition.gd`、引き継ぎ仕様 2-5）。開けた島に道が何通りもあり、想定外でもルールに合った解き方は歓迎する。
3. **ひとりでも、4 人でも**: 同じ島を、ひとりなら装備や回り道で、協力なら能力を集める近道で解ける（ADR 0011 決定 2・8）。
4. **妨害をルールで止めない**【確定】: 下の 2.8。

### 2.7 新規要素/オリジナル要素

- 操作（W/A/S/D・ジャンプなど）を 1 つずつのトークンにし、世界のブロック・生き物・仲間へ貸し借りする。貸したあいだ自分はその操作を失う。
- 能力と同じ形で「禁止」も持ち運べ、禁止が常に優先される。禁止を手放すか、持ったまま別の道を探すかが選択になる（「札の庭」、ADR 0011）。
- 単発・繰り返し・信号の 3 つの発動方式と、音（鐘）を信号にした仕掛け。
- 1〜4 人の協力で、能力を集めると数だけ強くなる（上限なし）。それでも「全員がゴールに集まる」ので、集めた力を誰かが回す手間が残る（ADR 0011 決定 11）。

### 2.8 協力のルール: 全員でゴールに集まる・地形で設計する【確定】

- **全員がゴールに集まる**（ADR 0011 決定 9、2026-11-20 本人）: どのステージも、島ごとの条件に加えて、生きている全員がゴールの箱に入ったらクリア。死亡観戦中・途中入室で待機中の人は要らない。ひとりなら「自分がゴールに着く」。
- **ルールではなく地形で設計する**（ADR 0011 決定 10、2026-11-20 本人「システム的に妨害するとかは絶対にしたくない。自由な発想を妨げるから」）:
  - 「ゴールの中からは渡せない」のような規則は足さない。
  - 代わりにゴールを縁より 1 段低い窪みにし、窪みの中からは下の仲間を狙いにくくした。渡したければ縁まで出ればよい（禁止はしない）。
  - 窪みから下の仲間への視線が地形で遮られることは、自動テスト（`tests/integration/test_goal_sightlines.gd`）で島ごとに確かめている。カメラを高く上げれば狙える場合があり、「難しくする」までで「できなくする」ではない。

### 2.9 1〜4 人のオンライン協力【確定】

| 項目 | 内容 | 根拠 |
|---|---|---|
| 通信方式 | 専用サーバーなし。プレイヤーの 1 人がホストになり、ホストが状態（能力の台帳・ブロック・ステージ）を確定する（ホスト権威）。参加者は「渡したい・回収したい」という依頼だけを送る | ADR 0006 |
| 提出版の接続 | ソロと、Steam なしの直接接続（IP アドレス＋ポート 24565）。審査は ZIP の実行ファイルで行うため、Steam クライアントを前提にしない | ADR 0006・0012、`docs/how-to-test.md` 2 |
| 仲間へ渡す | 承認なしで直接渡せる。F で回収した人が受け取る。単発の返還は直前に貸した人へ | ADR 0005 |
| 死亡と復活 | 落ちると観戦になり、世界は戻らない。生きている人が 1 人でもチェックポイントに着けば共通で有効になり、台座で全員復活 | ADR 0007 |
| 全員リセット | 過半数の投票（1/1・2/2・2/3・3/4）で、チェックポイントの時点まで世界ごと戻す。全員が落ちたら自動 | ADR 0007 |
| 途中参加 | 観戦で待ち、次の全員リセットで合流。人数別の補助アイテムもそのときだけ組み直す | ADR 0007・0009 |
| ホストが落ちたら | 全員が同じ情報から新しいホストを選び、最後の状態から続ける（「ホスト選出中…」）。できなければ失敗と出す | ADR 0010 決定 6 |
| 報酬 | 死亡観戦中・通信切断中（部屋が残っている間に戻れば）の人も受け取る。クリア前に自分で抜けた人は受け取らない | ADR 0008 |

限界（正直に書く）: インターネット越しではホスト側のルーターで UDP 24565 のポート開放が要る（`docs/how-to-test.md` 2）。別々の PC・インターネット越しの協力は、まだ人の手で試していない（`docs/requirements-status.md` の最後）。

ステージは「目安のクリア時間（ひとりで初めて遊ぶ想定）」の短い順に並べ、本人の試遊で実際の時間を測って直す（ADR 0011 決定 1）。

### 3.2 操作方法【確定】

| 操作 | キーボード・マウス | ゲームパッド（Xbox 風の並び） |

### 3.3 プレイ環境の構築方法説明資料（2 次審査で使用。記載必須）

提出する ZIP は 2 つ（どちらも `tools/check.sh --build` で作り、`tools/check_submission.py` で中身を確かめる。`docs/submission/checklist.md`）。

| ZIP | 中身 |
|---|---|
| `rule-relay-windows.zip` | `rule-relay.exe`（ゲームのデータを埋め込んだ 1 つのファイル）、`LICENSES.txt` |
| `rule-relay-macos.zip` | Mac のアプリ（`.app`、Intel・Apple シリコン両対応）、`LICENSES.txt` |

インストールは要らない。Steam・追加のランタイム・アカウント登録も要らない。

**Windows**
1. ZIP を展開して `rule-relay.exe` を起動する。
2. 「Windows によって PC が保護されました」と出たら、「詳細情報」→「実行」を押す（署名していない exe のため。ADR 0001「欠点・リスク」）。
3. 「部屋を作る」とき、ファイアウォールの許可を聞かれたら許可する。

**Mac**
1. ZIP を展開してアプリを開く。
2. 署名・公証済みの版なら、そのまま開ける。署名なしの版で「開発元を確認できません」と出たら、アプリを右クリック →「開く」（`docs/how-to-test.md` 0）。
   - 【未決・本人が決める】提出する Mac 版を署名・公証済みにするか（Apple Developer Program が要る。`docs/macos-signing.md`）。
3. 「部屋を作る」とき、受信接続の許可を聞かれたら許可する。

**ひとりで遊ぶ**: タイトルで「ひとりで遊ぶ」→ ハブの入口の上で F。

**協力で遊ぶ（2〜4 人）**
1. ホスト: タイトルで「部屋を作る」（ポート 24565）。
2. 参加者: 「部屋に入る」で、ホストの IP アドレスとポート 24565 を入れる。同じ LAN ならそのまま、インターネット越しならホスト側で UDP 24565 のポート開放が要る。
3. 1 台で試すとき: 2 つ起動し、2 つ目は記録の名前を変えて `127.0.0.1` に入る。Windows と Mac の組み合わせでもつながる（ゲームの版はそろえる）。

【未決・本人が決める】審査員が 1 人で協力プレイを確かめる方法の案内（1 台で 2 つ起動する手順を載せるか）。
