# ゲームプレイ動画の撮影計画（20 分以内）

- 状態: 下書き（2026-11-20 作成、**2026-11-22 に v0.3.0 の中身に合わせて撮影リストを作り直した**）。ステージの題・番号・目安時間はすべて仮（ADR 0011・0013、`docs/campaign-plan.md`）。タイトル・物語が決まったら、冒頭とエンドカードの文字と字幕を直す。
- 公式の条件（https://gc2026.jp.square-enix.com/ 、2026-11-22 に読み直した）: YouTube に**限定公開**し、その URL を提出する。**最大 20 分**。動画の形式（解像度・フレームレート・ファイル形式）の指定は公式サイトに無い。1 次審査は企画書とこの動画で行われる（公式サイト）。
- 長さの目標: **19 分 00 秒**（20 分の上限に 1 分の余裕。アップロード後の長さを YouTube の表示で確かめる）。
- 方針（AI の提案。本人はまだ確かめていない）: 最初の 3 分で「操作を貸す」「貸すと自分はできなくなる」「ルールは厳格、解法は自由」を見せきる。審査員は最後まで見るとは限らない。その後、広場の広がり・動物・仕掛けの種類・協力を見せる。
- 素材の一部は自動で撮れる: `tools/capture_video.sh`（`docs/submission/video-capture.md`）。下の表の「自動の素材」の列がそのクリップ。自動の素材はソフトウェア描画の短い場面なので、**提出の動画は Windows 実機で撮り直すのが基本**で、自動の素材は編集の下書き（どの場面をどの長さで見せるか）に使う。

## 撮る前に決めること（本人）

- 【未決・本人が決める】タイトル（いまは「（タイトル未定）」。候補は `docs/title/`）と物語の一言（冒頭とエンドカードの文字）。
- 【未決・本人が決める】見た目の仕上げ。いまの見た目のまま撮るなら、字幕で「見た目は開発中」と断るか。
- 【本人だけができる】協力の場面には 2〜4 人の人と PC が要る（AI は実時間で操作できない）。自動の素材では、同じ PC の中で 2 人の場面だけ作れる（`coop_jumps`）。
- BGM: ゲームの BGM（Stable Audio 3 medium で作った 3 曲、仮の選曲。`docs/sound-design.md`）をそのまま使う。曲を差し替えたら `docs/ai-usage.md` と企画書 3.6 も直す。動画だけに別の音源を足すなら、権利を確かめる。

## 撮り方

- Windows 11 実機（GPU あり）で、1920×1080・60fps。ソフトウェア描画の画面は使わない（色と明るさが違う）。
- 協力の場面は、主役の 1 人の画面を中心に、要所だけ 2 分割・4 分割で仲間の画面も見せる。
- 操作の案内（HUD）は出したまま。何を押したかが分かるように、要所に字幕（「ジャンプをブロックへ貸す（単発）」など）。
- 入力の表示は、ゲームパッドとキーボードのどちらか一方にそろえる（`docs/how-to-test.md`「ゲームパッドで遊ぶ」）。
- 試遊版は全部のステージ・地方が開いている。広場が育つ様子（住む動物・建物・橋）を撮るなら、起動の引数 `-- --campaign` で製品と同じ開き方にし、順にクリアした記録で撮る。
- 個人の名前・IP アドレスが映らないようにする（「部屋に入る」の入力画面、記録の名前、OS の通知）。

## 撮影の前に確かめること

- 撮るビルドで `tools/check.sh --build` が「all checks passed」。動画のビルドと提出の ZIP は同じ版にする（審査員が動画と同じものを遊べるように）。
- 「残す」と決めた技（縁ちょうどの幅 4 越え・ブロックの上昇＋自分のジャンプ・どの地面のセルも持ち上げ台にできる。ADR 0013）を動画で見せるかは【未決・本人が決める】。
- 動画の中の音は、ゲームの音（効果音と BGM）だけにする。声や他人の音源を入れるなら権利を確かめる。自動の素材にはゲームの音が入っている（`docs/submission/video-capture.md`）。

## アップロード（本人だけができる）

- YouTube に**限定公開**でアップロードし、URL をエントリーフォームに入れる（`docs/submission/checklist.md`）。
- 公開範囲が「限定公開」になっていること、ログインしていないブラウザで URL から見られることを確かめる。
