# ゲームプレイ動画の撮影計画（20 分以内）

- 状態: 下書き（2026-11-20）。ステージ名・目安時間はすべて仮（ADR 0011）。世界観・タイトル・アートスタイルが決まったら、撮る場面と字幕を直す。
- 公式の条件: YouTube に**限定公開**し、その URL を提出する。最大 20 分（公式サイト）。1 次審査は企画書とこの動画で行われる。
- 長さの目標: **19 分 00 秒**（20 分の上限に 1 分の余裕。書き出し・アップロード後の長さを YouTube の表示で確かめる）。
- 方針: 最初の 3 分で「操作を貸す」「貸すと自分はできなくなる」「ルールは厳格、解法は自由」を見せきる。審査員は最後まで見るとは限らない。

## 撮る前に決めること（本人）

- 【未決・本人が決める】タイトル・世界観（冒頭とエンドカードの文字）。`docs/worldview/` の案。
- 【未決・本人が決める】アートスタイル。仮の見た目のまま撮るなら、字幕で「見た目は開発中」と断る。
- 【本人だけができる】協力の場面には 2〜4 人の人と PC が要る（AI は実時間で操作できない）。
- BGM: ゲームの BGM（Stable Audio 3 medium で作った 3 曲、仮の選曲。`docs/sound-design.md`）をそのまま使う。曲を差し替えたら `docs/ai-usage.md` と企画書 3.6 も直す。動画だけに別の音源を足すなら、権利を確かめる。

## 撮り方

- Windows 11 実機（GPU あり）で、1920×1080・60fps。ソフトウェア描画の画面は使わない（色が違う）。
- 協力の場面は、主役の 1 人の画面を中心に、要所だけ 2 分割・4 分割で仲間の画面も見せる。
- 操作の案内（HUD）は出したまま。何を押したかが分かるように、要所に字幕（「ジャンプをブロックへ貸す（単発）」など）。
- 入力の表示は、ゲームパッドとキーボードのどちらか一方にそろえる（`docs/how-to-test.md`「ゲームパッドで遊ぶ」）。
- 個人の名前・IP アドレスが映らないようにする（「部屋に入る」の入力画面、記録の名前、OS の通知）。

## 撮影の前に確かめること

- 撮るビルドで `tools/check.sh --build` が「all checks passed」。動画のビルドと提出の ZIP は同じ版にする（審査員が動画と同じものを遊べるように）。
- 縁ちょうどの幅 4 越え（F1）・ブロックの上での高跳び（F2）は「残す」と決めた技。動画で見せるかは【未決・本人が決める】。
- 動画の中の音は、ゲームの音（効果音と BGM）だけにする。声や他人の音源を入れるなら権利を確かめる。
